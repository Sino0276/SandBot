# 가정값·근사값 정리

SandBot의 시뮬레이터·편집기에 들어 있는 값 가운데 출처로 확인하지 못한 값(가정), 다른 제품·조건에서 끌어왔거나 모델을 단순화한 값(근사), 실물로 재야 하는 값을 한곳에 모은다. 팀이 실제 로봇·필드에서 재면 무엇을 어떻게 바꾸면 되는지도 적는다.

- 코드 주석의 `[가정: …]`·`가정` 표시(`src/**`, `sidecar/**`)와 CLAUDE.md의 "가정"·"실측이 필요한 값" 목록을 모두 훑었다(6a 병합 뒤 기준: 물리·렌더러가 더한 표시도 넣었다).
- 출처를 확인한 값(`[확인: …]`, 제조사 데이터시트·FTC SDK 소스·공식 CAD에서 잰 값)은 넣지 않는다.
- 6a(공 물리)는 물리 구현(`elements/elementWorld.ts` 등)과 렌더러가 들어온 뒤의 실제 위치를 적는다.
- 근거로 적은 조사 문서(`p10mass/…`, `p11joint/…`, `p12drive/…`, `p13field/…`, `p14collide/…`)는 저장소 밖 작업 폴더에 있다. CLAUDE.md가 같은 이름으로 가리킨다.

## 읽는 법

열은 항목 · 값 · 위치(파일·상수) · 근거·출처 · 측정 방법 · 상태다.

상태는 다음 가운데 하나다.

- **실측 필요**: 출처 없이 정한 값이고 결과(주행·관절·센서 값·비전)에 크게 영향을 주거나, CLAUDE.md의 "실측이 필요한 값" 목록에 있는 값이다.
- **가정**: 출처 없이 정한 값. 영향이 작거나 팀 칸으로 덮을 수 있다.
- **근사**: 출처가 있는 값에서 끌어왔거나(다른 제품·전압·로봇) 모델을 단순화한 값.
- **결정**: 설계로 정한 값이다. 재는 값은 아니지만 바꿀 수 있다. 물리 결과에 닿는 것만 적었다. "결정(실측 목록)"은 설계 값이지만 CLAUDE.md 실측 목록에 있어 실물과 견줘 다시 정할 값이다.
- **수치**: 반올림·수렴·검증용 상수다. 물리 값이 아니라 재지 않는다.
- **표시만**: 계산에 쓰지 않는 그리기 값.

위치는 줄 번호 대신 파일과 상수 이름으로 적는다(줄은 자주 바뀐다). 표마다 기준 폴더를 적고, 다른 폴더의 파일은 저장소 루트부터의 경로로 쓴다.

측정 방법에 "팀 칸"이 있는 값은 코드를 고치지 않고 인스펙터나 환경 설정에 잰 값을 넣으면 된다. 코드 기본값은 팀이 아무것도 넣지 않았을 때 쓰는 값이다.

## 고치는 법

1. **새 가정값을 넣을 때:** 상수 옆 주석에 `[가정: 한 줄 이유]`를 단다. 이 파일의 해당 단계 표에도 한 줄을 더하고, 새 단계면 표를 새로 만든다.
2. **값을 실측했을 때:** 코드 값을 바꾸고 주석을 `[확인: 측정 방법·조건·날짜]`로 바꾼다. 이 파일에서는 그 줄을 지우고, 맨 아래 "실측으로 바꾼 값"에 이전 값과 함께 옮긴다.
3. **기준 해시를 확인한다:** `src/shared/sim`의 값을 바꾸면 `src/shared/sim/worldGolden.test.ts`의 기준 해시가 바뀔 수 있다. `pnpm test src/shared/sim/worldGolden.test.ts`로 어느 해시가 바뀌었는지 본다. 그 값을 쓰는 해시만 바뀌었으면 커밋 메시지에 까닭을 적고 해시를 고친다. 다른 해시까지 바뀌었으면 다른 곳을 건드린 것이다. 해석 시험의 기대값과 사이드카 통합 시험(`sidecar/tests/sim.test.ts` 등)도 다시 본다.
4. **위치를 맞춘다:** 상수 이름을 바꾸거나 파일을 옮기면 이 표의 위치도 고친다. 훑을 때는 `grep -rn "가정" src sidecar --include=*.ts --include=*.tsx --include=*.java`를 쓴다(`sidecar/build`는 뺀다).
5. **팀 칸이 먼저다:** 팀마다 다른 값(바퀴 μ, 저울 무게, 관절 마찰, Collider 마찰, Hub 타이밍, 웹캠 보정)은 팀 칸에 넣는다. 코드 기본값은 여러 팀에 공통으로 맞는다는 근거가 생겼을 때만 바꾼다.

## 먼저 잴 값

결과에 가장 크게 영향을 주고 팀이 잴 수 있는 값이다. 순서는 영향이 큰 차례다.

1. 바퀴–타일 마찰 μ(3c): 출발 미끄럼, 벽 밀기, 견인 한계를 정한다. 팀 칸은 바퀴 카드 마찰이다.
2. 롤러·굴림 저항(3c): FLOAT 감속과 옆걸음 속도 비를 정한다. Pedro 튜너로 잰다.
3. 로봇 질량·무게중심(3a): 저울 무게는 팀 칸이고, 무게중심 높이는 기울임 시험으로 잰다.
4. Hub 타이밍(사이드카): 루프 시간을 정한다. 팀 칸은 환경 설정 › 시뮬레이션이다.
5. 허브 기본 PIDF·제어 주기(3b): RUN_TO_POSITION·RUN_USING_ENCODER 응답을 정한다.
6. 회전자 관성·역구동 마찰·기어 효율(3b): 관절 처짐과 급정거를 정한다.
7. 재질 반사율 표(4ab·4c): 거리·컬러 센서 값을 정한다.
8. 거리 센서 문턱과 컬러 K·E_a(4c).
9. 웹캠 처리 시간·검출 한계·포털 전이 시간(4d).
10. Collider·바닥 마찰(5), 공 강성·반발·마찰·굴림 저항(6a).

## 훑기에서 뺀 것

`가정`이라는 낱말이 있지만 값이 아닌 곳이다.

- `src/shared/sim/worldSpec.ts`의 외곽 검사 주석: 구조물 접촉이 "가정한다"는 전제 조건(단순 볼록 반시계 외곽)이다.
- `src/shared/sim/motorTypes.ts`의 `gearing` 주석: SDK 모터 형식이 정한 감속비다(SDK 값).
- `src/renderer/src/mass/nameRules.ts` 머리 주석: 출처 없는 일반 낱말(mount·block·hub)을 규칙에 넣지 않는다는 설명이다.
- i18n 문구(`src/renderer/src/i18n/locales/ko.ts`·`en.ts`)의 `sharedEncoderMode` 안내와 바퀴 마찰 도움말: 3b·3c 표의 값을 사용자에게 설명한다.
- 시험 파일(`*.test.ts`, `sidecar/tests/**`)의 같은 값 주석: 제품 코드의 값을 시험이 다시 적은 것이다.
