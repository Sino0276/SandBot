# 6b HIVE 넘어감·CELL 트레이·FLOWER 케이지 (6단계의 둘째 하위 단계)

## Context

6a로 공(POLLEN·NECTAR)이 6자유도 몸체로 움직이게 됐지만, HIVE는 실행 동안 시작 상태로 고정이고(CELL은 표시만, 공이 지나감), FLOWER는 꽉 찬 상자라 공을 넣거나 아래로 꺼낼 수 없다. 그래서 BIOBUZZ의 중심 동작(CELL에 쏘아 HIVE를 넘기기, FLOWER에 넣고 꺼내기)을 시험할 수 없다.

6단계 나눔(사용자 결정 11/13): 6a 공 물리 → **6b HIVE·FLOWER(이번)** → 6c 센서·웹캠이 공을 봄 → 6d 점수·규칙 알림·사람 선수 NECTAR·AUTO→TELEOP 이어 가기.

### 사용자 결정 (11/19)

- **값:** 가정값으로 시작한다. HIVE 넘어감 기준만 공식 보정표에 맞추고, 관성·댐퍼(반발 없는 단단한 멈춤)·축 마찰·FLOWER 치수는 매뉴얼 수치와 그림 근사로 정해 `[가정]`으로 적는다(`docs/assumptions.md`에 측정 방법과 함께).
- **CELL 모양:** 바깥 끝(축에서 먼 쪽)이 열리고 안쪽 끝이 Back Skin인 트레이. **오각형 단면까지 맞춘다**(필드 가이드 그림으로 지붕 경사를 근사, 치수는 `[가정]`).
- **FLOWER 상세 형상은 공과 로봇 3D 충돌에 쓴다.** 인테이크가 아래 회수 구멍으로 POLLEN을 꺼낼 수 있다. 8째 기준 해시(로봇이 FLOWER `<3>` 옆을 미끄러짐)는 이유와 함께 다시 잰다. 4c 거리·컬러 광선, 4d 카메라 가림, 평면 경로(로봇 카드 계산), 시작 프리셋·열기 겹침 판정은 지금 상자 그대로다(6c에서 센서가 공을 볼 때 다시 본다).
- **로봇 몸체는 HIVE에 닿지 않는다(지금처럼).** HIVE 가장 낮은 곳 30.65 in > 로봇 확장 높이 한도 29 in, G417. 로봇이 쥔 공이 HIVE에 닿으면 그 공을 통해 같은 풀이로 서로 민다.

### 권장 기본값 (따로 묻지 않음, 바꿀 수 있음)

- 개인 실행 설정 `hiveState`는 **시작 상태**가 된다. 넘어간 채 시작하면 NECTAR 3은 그때 위를 보는 CELL에 둔다. 경기 요소를 끄면 HIVE는 시작 상태로 고정이다(넘길 공이 없다).
- Console 알림 `hiveTip`(HIVE마다 실행에 한 번, 횟수·점수는 6d).
- HIVE가 든 섬은 조밀 풀이 한도를 따로 둔다(넘어감 기준이 PGS 근사로 흔들리지 않게).
- 프로젝트 파일은 바꾸지 않는다(`PROJECT_VERSION` 14 그대로). 시즌 데이터와 세계 설명만 바뀐다.

## 설계 요약 (상세는 `spec-6b.md`)

### 1. HIVE: 한 축으로만 도는 몸체

- HIVE마다 좌표 하나 θ(필드 +Y축 둘레, 축 = 피벗, 빨강 시작 −π/6·넘어간 +π/6, 파랑은 부호 반대). 6a 공과 같은 하위 단계 격자에서 공 섬에 든다.
- **공의 "몸체 부분"을 일반화:** HIVE를 공 번호 뒤의 마디로 두고 속도 칸 6개 중 ω_y 하나만 쓴다(역질량 0, 역관성 1/I). 그래서 `articulation.ts`·`islands.ts`·`denseLcp.ts`는 바꾸지 않고 공만 있는 풀이는 비트 그대로다. 로봇이 쥔 공이 HIVE에 닿으면 HIVE가 로봇 섬에 같이 들어간다.
- 중력: 무게중심이 축 위에 있는 시소. τ = (M·c)·g·sin θ(명시), 멈춤은 한쪽 구속 행 둘(반발 0, 단단한 댐퍼 `[가정]`), 축 마찰은 고정 상자 행 `[가정]`.
- **보정:** M·c(질량 모멘트)를 공식 보정표에 맞춘다. 시뮬레이터로 보정표의 짐을 Back Skin에 놓아 받침 토크를 재고, 안 넘어가야 할 짐(3N+2P, 7P)의 최대와 넘어가야 할 짐(3N+3P, 8P)의 최소 사이 가운데에 둔다 `[결정]`. 시험이 보정표 여섯 줄(살며시 놓기·던지기)을 그대로 다시 한다.
- 잠들기: 멈춤에 기대 쉬는 HIVE는 잠들고 θ는 멈춤 각 그대로다(비트). 공이 닿으면 깬다.
- 넘어감 알림 `hiveTip`과 HIVE 상태(각·각속도·넘어간 횟수)를 공 스냅샷과 따로 둔다(기준 해시 아홉째 보존, 6d 이음새).

### 2. CELL 트레이

- CELL을 HIVE 몸체 틀의 얇은 판들(밑판·Back Skin·옆벽 둘·지붕 둘)로 바꾸고 바깥 끝을 연다. 공만 닿는다(로봇은 닿지 않음, 센서·카메라도 지금처럼 보지 않음).
- 위로 향한 CELL에서 중력이 공을 Back Skin 쪽으로 굴리고, 넘어간 뒤 아래로 향한 CELL에서는 공이 열린 끝으로 쏟아진다(물리에서 저절로).

### 3. FLOWER 케이지

- FLOWER 구조물에 부품 목록(관 넷, 위·가운데·아래 고리, 백스톱, 벽 쪽 압출재)을 더한다. 구조물 번호 `s<i>`는 그대로고 부품 토큰은 `s<i>p<k>`다.
- 공: 정확한 기본형(세운 원기둥, 고리 = 속 빈 원기둥, 상자·볼록 기둥). 로봇: 볼록 조각(원기둥은 16각 기둥, 고리는 22.5° 조각).
- 상자는 4c 광선·4d 가림·평면 경로·시작 프리셋·열기 알림·자동 프리로드가 그대로 쓴다. INIT 3D 시작 겹침은 3D 충돌과 같은 케이지다.

### 4. 시작 배치 묶음

- `flower`(FLOWER마다 POLLEN 4, 16개), `hiveCell`(위로 향한 CELL마다 NECTAR 3, 6개). GARDEN 8 + 16 + 6 + 프리로드 4 = 34 ≤ 64.
- `hiveCell` 자리는 HIVE 몸체 틀에 적고 시작 상태로 위를 보는 CELL을 고른다.

### 5. 카메라·표시

- 4d 웹캠의 태그 자세가 프레임마다 HIVE 각을 따른다(시작 각과 같으면 지금과 비트로 같은 길).
- 씬 뷰: 실행 중 HIVE(CELL 트레이·태그)가 시뮬레이터 각으로 움직이고, 끝나면 시작 상태로 돌아가며 끝난 각이 다르면 잔상. FLOWER는 케이지로 그린다(안의 공이 보이게).
- Field 인스펙터: FLOWER·HIVE CELL 공 수가 살아나고, HIVE 상태 칸은 "시작 상태"가 된다.

### 6. 판·해시

- `WORLD_SPEC_VERSION` 7 → 8(배치 묶음 둘, HIVE 동역학). `PROJECT_VERSION` 14 그대로. 사이드카 프로토콜 4 그대로. 메시 캐시 `model-v5` 그대로.
- 기준 해시: 1–7·9째 그대로, **8째 다시 잼**(FLOWER 케이지), **10째 새로**(HIVE 넘어감 + 쏟아짐 + 웹캠 태그 + FLOWER 회수 구멍).
