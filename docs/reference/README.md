## 읽는 법

- 각 문서는 같은 틀이다: 목차 → 읽는 법(상태 표기) → 범위·파일·데이터 흐름 → 단계별 상수·식 → 시험 기준 → **알려진 한계·남은 일** → **원본 조사 자료 상태**.
- 표 열은 항목 · 값 · 단위 · 위치(파일·상수) · 상태·근거다. 위치에 줄 번호는 없다(줄은 자주 바뀐다). 경로는 문서마다 맨 앞에서 기준 폴더를 밝힌다.
- 상태 표기: **[확인]** 코드 주석이 출처(SDK 소스·제조사 페이지·공식 CAD)를 적은 값, **[가정]** 출처 없이 정한 값(실측·팀 칸으로 바꿀 대상), **[결정]** 설계로 정한 값(사용자 결정은 그렇게 적음), **코드 값** 주석에 태그가 없는 값, **계산값** 문서를 쓰며 코드를 돌려 구한 값·환산, **출처 기록 없음** 코드·CLAUDE.md·`docs/assumptions.md` 어디에도 출처가 없는 값.
- 숫자를 문서만 보고 고치지 않는다. 값을 바꾸면 코드 상수·주석·이 문서·`docs/assumptions.md`를 함께 고친다(CLAUDE.md의 "가정값은 두 곳에 적는다").

## 어떻게 만들었고 얼마나 믿을 수 있나

1. 영역마다 한 에이전트가 코드(상수·식·표)와 CLAUDE.md의 해당 단계 절을 읽어 문서를 썼다. 코드를 직접 실행해 얻은 값(환산·묶음 원점·튜너 결과 등)은 "계산값"으로 표시했다.
2. 다른 에이전트가 문서의 수치와 식을 코드와 한 줄씩 대조했다. 대조한 항목 수와 틀린 수는 아래와 같다. 틀린 것은 고쳤다(주로 반올림한 값·인용 위치·함수 이름). 지어낸 출처가 없다고 보고한 검증이 넷(field-biobuzz·motors-joints·drivetrain·collision)이고 나머지 다섯은 이 점을 따로 적지 않았다.

## 추적되지 않는 것 (모든 문서 공통)

3a–5단계의 **원본 조사·명세 문서**(`p10mass`·`p11joint`·`p12drive`·`p13field`·`p14collide`의 `research/*`·`spec-*`·비평·기준 스크립트)는 저장소에 없고 되살릴 수 없다. 6a 명세·계획만 `docs/research/6a/`에 있다. 따라서:

- **일차 출처**(제조사 데이터시트의 표·그림 번호, 공식 CAD에서 잰 측정, 논문·FTC 매뉴얼의 절)는 코드 주석에 적힌 이름·URL까지만 추적된다. 각 문서는 이를 다시 열어 확인하지 않았고 "코드 주석 그대로 옮김"이라고 밝혔다.
- 주석의 `spec-3b §…`·`synthesis §…`·`critique E13` 같은 문서 번호는 가리키는 곳이 없다. 그 문장이 설명하는 결정의 이유는 주석에 적힌 한 줄뿐이다.
- 값의 대부분은 **[가정]**이다(공 접촉·공기, 마찰 계수, 허브 PIDF·주기, 회전자 관성, 재질 반사율, 비전 처리 시간 등). 실측해 바꿀 때의 방법은 `docs/assumptions.md`의 "측정 방법" 열과 각 문서의 한계 절에 있다.
- 공식 필드 CAD 측정(벽·구조물·태그 위치, 다리 SVD 맞춤)과 PnP 기준값은 원본 파일·스크립트가 없어 코드·시험이 고정한 숫자로만 남아 있다(`field-biobuzz.md` §20, `sensors-vision.md` §22). 다시 만들려면 FIRST 공식 필드 CAD와 OpenCV 4.10.0이 필요하다(CLAUDE.md의 `scripts/vision-pnp-oracle.py`).

## 문서를 쓰며 찾은 불일치 (코드·CLAUDE.md는 건드리지 않았거나 한 줄만 고침)

- CLAUDE.md 3a 한계의 "서보는 60 g 하나다"는 `servoModel`별 질량 표(`mass/cotsTable.ts`) 도입 전 서술이라 고쳤다.
- 사이드카 `package-info.java`는 모터 power가 "꺼져 있거나 리셋이면 0"이라고 적었지만 코드(`Channel.publish`)는 리셋일 때만 0으로 만든다. `sidecar-time.md`가 코드 동작을 적었고 주석은 그대로다.
- `RunRequest.timing`(Hub 타이밍 비용표 덮어쓰기)은 프로토콜에 있으나 앱이 늘 빈 객체를 보내고 환경 설정에 비용표 칸이 없다. `docs/assumptions.md`의 "팀 칸: 환경 설정 › 시뮬레이션 Hub 타이밍"은 오차·시드 칸만 말한다.
- 코드 주석의 일부 숫자가 다시 계산한 값과 다르다: Pedro 튜너 맞춤 앞 감속 0.879 대 이 트리 0.8813 m/s²(`drivetrain.md`), goBILDA 웹캠 `crop`의 "fx 1.000배"가 1920×1080에서 0.990배(`sensors-vision.md`), `TOF_BIAS`·`TOF_NORM` 마지막 자리(`sensors-vision.md`), COTS `motorCotsKey` 주석의 "최대 38 g"(`mass.md`).
- 문서가 길다(합쳐 약 9천 줄). 표 위주라 처음부터 읽기보다 찾아 읽는 용도이고, 먼저 각 문서의 목차와 "알려진 한계·남은 일"을 본다.
