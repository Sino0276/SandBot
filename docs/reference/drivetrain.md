# 구동계·바퀴–타일 마찰(3c) 기준 문서

이 문서는 SandBot 시뮬레이터의 3c 단계(구동계 동역학: 바퀴–타일 쿨롱 마찰, 메카넘·옴니 롤러 저항, 굴림 저항, 법선 하중 이동, 평면 부유 기저, 필드 벽 접촉, 바퀴 질량·회전 관성)가 쓰는 모든 치수·상수·표·수식·결정사항을 한곳에 적는다. 원본 조사·명세 문서(`p12drive/research/{data,method,critique}.md`, `spec-3c`)는 저장소 밖 작업 폴더에 있다가 사라졌으므로, 코드(`src/shared/sim/contact.ts`, `wheelData.ts`, `wheelLoads.ts`, `drivetrain.ts`, `driveTestkit.ts`, `articulation.ts`의 기저·접촉 부분, `world.ts`, `worldSpec.ts`의 바퀴·섀시 검증, 렌더러 `play/worldSpec.ts`·`scene/wheel.ts`·`editor/hardware/wheelCardModel.ts`)와 CLAUDE.md의 서술이 곧 원본이다. 각 값은 값 · 단위 · 위치(파일·상수·함수 이름, 줄 번호 없음) · 상태(코드 주석의 `[확인: …]` 출처 확인, `[가정: …]` 출처 없는 가정, `[결정: …]` 설계 결정, "맞춤 값"은 Pedro 튜너 맞춤으로 정한 값, 표시 없는 코드 값)와 근거를 적었고, 코드에 출처가 없으면 "출처 기록 없음"이라고 썼다. "계산값"은 코드에 상수로 없고 이 문서를 쓸 때 코드의 식으로 다시 계산한 값이다. 수식은 코드의 변수 이름을 그대로 써서 다시 구현할 수 있게 했다. 단위는 내부 SI(미터·라디안·N·N·m·초)다. 모터·허브 제어·LCP 풀이의 일반 서술은 같은 폴더의 `motors-joints.md`(3b), 필드 벽·구조물 접촉은 `field-biobuzz.md`(4ab)를 가리킨다.

### 1.2 데이터 흐름

1. 팀이 하이어라키 오브젝트(파트·어셈블리·그룹)에 바퀴(`SceneObject.wheel`: 종류·지름·구동 모터·외부 감속비·굴림 방향·롤러·마찰)를 붙이고, 모터는 하드웨어 컴포넌트로 따로 붙인다.
2. INIT 때 렌더러 `buildWorldSpec`이 그 로봇의 바퀴 목록(`robotWheels`), 섀시 몸체(`chassisBody`), 모든 모터의 데이터시트 값(`motorComponentParams`)으로 세계 설명(`SimWheelSpec[]`·`robot.body`·`robot.footprint`·`robot.height`)을 만든다.
3. 메인 `parseWorldSpec`이 모양·한도·참조를 확인한다(§16.2). 시뮬레이터는 렌더러가 보낸 바퀴 값을 믿지 않고 한도만 본다.
4. `PhysicsWorld` 생성자가 관절에 묶이지 않은 좌표(바퀴 모터·구동하지 않는 바퀴)와 armature를 만들고, 바퀴가 하나라도 있으면 `Articulation`에 평면 부유 기저를 단다(§5, §12).
5. 틱마다 `step(tNanos, outputs)`가 앞 틱의 출력으로 [이전 틱, 이번 틱] 구간을 1 ms 절대 격자 하위 단계로 나눠 적분한다. 하위 단계마다 ① 허브 제어 표본(10 ms) ② 바퀴 법선 하중 ③ 바퀴·벽·구조물 행 ④ LCP 풀이 ⑤ 오도메트리 순이다(§12.3).
6. 틱 경계에서 모터 position·velocity·current, 데드휠·Pinpoint·OTOS·IMU 값을 사이드카로 돌려준다(§13).

| 중력                    | `GRAVITY` = 9.80665 m/s²(NIST g_n 정의값), 로봇 좌표 (0, 0, −g)                                                                                                                                                                                                                                           |

### 2.1 미끄럼 속도와 행 야코비안

바퀴 i의 접점 p(로봇 좌표, 바닥), 굴림 u, 방향 d(로봇 좌표), 바퀴 좌표 k의 각속도 φ̇_k, 바퀴 회전당 이동 `rollPerRad`(구동 바퀴 r / G_ext, 구동하지 않는 바퀴 r)일 때 방향 d의 접점 미끄럼 속도는

```
g_d = d_f · (v + ω ẑ × R(yaw)·p) − (d·u) · rollPerRad · φ̇_k          d_f = R(yaw)·d
```

이고, 행 J_d(z 공간)는

```
J_d[0] = c·d.x − s·d.y                 (c = cos yaw, s = sin yaw: 기저 vx 성분)
J_d[1] = s·d.x + c·d.y                 (기저 vy 성분)
J_d[2] = −d.x·p.y + d.y·p.x            (= d·(ẑ × p), 로봇 좌표라 요와 관계없음: 기저 ω 성분)
J_d[k] = −(d·u) · rollPerRad           (바퀴 좌표 k)
```

(`contact.ts` `slipRow`). 모든 바퀴 행의 목표(target)는 0이다(미끄럼 속도 0을 향해 상자 안에서 힘을 낸다).

## 3. 바퀴·타일·벽 물리 값(μ·롤러 저항·굴림 저항·벽 마찰)

### 3.1 바퀴 종류 기본 겉보기 마찰 계수 μ

겉보기 μ는 "잠근 바퀴를 FTC 타일에서 끌 때의 마찰 계수"(제조사 CoF 표기, 정지 = 운동)이고, 로봇이 미끄러지며 내는 가속 ≈ μ·g다. 바퀴 카드 마찰 칸이 0이거나 비면 종류 기본값을 쓴다(`effectiveWheelFriction`).

| ------------------- | ------ | ---- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 메카넘 기본 μ       | 0.6    | -    | `wheelData.ts` `DEFAULT_WHEEL_FRICTION`                                                    | [가정: AndyMark 4" SD 메카넘 "Forward / Reverse Coefficient of Friction: 0.51 on FTC Soft-tile", "Sideways CoF: 0.67"(https://www.andymark.com/am-2626)의 사이]. goBILDA GripForce(40A)는 숫자를 공개하지 않는다. ### 3.3 롤러 저항 배율 k와 메카넘 견인 계수 μ_r

```
k   = min(1, μ / μ_기본(종류))                 rollerResistanceScale   (일반 바퀴는 쓰지 않음, wheelContact는 1을 넣음)
μ_r = max(0, √2·μ − k·c_r)                      mecanumRollerFriction   (메카넘 롤러 축 방향 견인 행의 마찰 계수)
```

- k는 롤러 저항(점성·쿨롱)에 곱한다. 기본 μ 이상이면 1이라 Pedro 맞춤과 기본 동작이 그대로다. 근거: 미끄러운 바닥에서는 롤러가 구르지 않고 미끄러지므로 롤러가 전하는 저항도 바닥이 주는 마찰을 넘지 못한다 [가정: 바닥 μ에 비례하는 꼴은 출처 없음].
- k가 고정(1)이면(3c 리뷰) 메카넘은 μ ≈ 0.13 아래에서 옆걸음이 거꾸로 갔고(자유 방향이 굴림과 45°라 바퀴 회전이 그 미끄럼을 만들어 저항 c_r + c_v·g_f가 롤러 축 견인 √2·μ − c_r을 넘으면 차대를 명령의 반대로 민다), 옴니는 μ ≤ c_r(0.076)에서 축 방향 미끄럼이 필요한 움직임(X 드라이브 직진, 탱크 제자리 돌기)이 멈췄다(축 상자가 견인보다 커서).
- 메카넘 옆걸음 순 힘은 k·(√2·μ_기본 − 2·c_r − c_v·g)·N/√2라 g < 18 m/s(`(√2·0.6 − 2·0.076)/0.038` = 18.33, 계산값, FTC 바퀴 면 속도의 두 배 넘게)면 늘 명령 방향이고(코드 주석의 g는 `contact.ts`의 미끄럼 속도 기호 g_d·g_f와 같은 롤러 자유 방향 미끄럼 속도 m/s이며 중력이 아니다), 옴니 축 저항은 견인의 c_r / 0.8 = 9.5 %를 넘지 않는다.
- μ_r = √2·μ − k·c_r인 까닭: 잠근 메카넘 바퀴를 앞이나 옆으로 끌면 접점이 롤러 축 a와 자유 방향 f로 같은 크기(cos 45°)만큼 미끄러지므로 바퀴 하나가 받는 힘은 (μ_r + k·c_r)·N·cos 45°다. 이것이 입력 μ(잠근 바퀴의 겉보기 계수)와 같아지게 μ_r을 정했다(spec-3c §1.3 "입력 μ는 잠근 바퀴의 겉보기 계수", 롤러 쿨롱은 맞춤이 더한 항). 자유 롤러는 축 방향으로만 힘을 전하므로 견인 행은 롤러 축 방향이다(method §4.1, Ether 해석).

### 4.4 도는 질량(`wheelSpinMass`) 결정 순서

바퀴 회전 관성에 쓰는 질량 m_wheel을 렌더러가 정한다(세계 설명과 인스펙터가 같은 함수를 쓴다).

1. 질량 모델이 없거나 그 오브젝트가 없으면 null(→ 종류 기본 질량, §4.2).
2. 바퀴 설정이 표의 메카넘 제품(§4.3)이고 바퀴 오브젝트에 질량 덮어쓰기가 없으면 그 제품의 데이터시트 질량 그대로(하위가 커서 COTS를 거절한 바퀴 그룹도).
3. 아니면 질량 모델의 바퀴 오브젝트 하위 질량에서 그 하위에 붙은 하드웨어 컴포넌트(모터·서보·Pinpoint 등)의 데이터시트 질량을 뺀다. 모터 회전자는 전기자 관성(J_rotor·G²)으로 이미 들어가 있고 하우징은 돌지 않는다.
4. 빼고 남은 것이 0 이하면 null.

그 결과를 `effectiveWheelMass`가 [0.01, 2] kg로 자른다. 인스펙터는 종류 기본 질량·잘린 값을 계산값과 다른 문구로 보인다(`wheelMassClipped`).

시험 기준 섀시(`testChassis`): `Ixx = Iyy = m·(side² + height²)/12`(13.6 kg, 0.4572 m, 0.2 m에서 0.28224 kg·m², 계산값), `Izz = m·2·side²/12`(0.47381 kg·m², 계산값). 무게중심 (0, 0, height/2)이고 시험이 `comHeight`·`comX`로 바꾼다.

섀시 몸체(`chassisBody`, 렌더러): 질량 모델의 로봇 전체(정보 없는 로봇의 외곽 상자 질량·바퀴 질량 포함)에서 관절 몸체들(세계 설명 관절 몸체와 같은 오브젝트 집합)을 평행축 정리로 뺀 나머지다(`subtractMassProps`: 질량·무게중심 모멘트를 빼고 나머지 무게중심 기준으로 관성을 옮겨 뺀다). 로봇 좌표, 무게중심 기준 관성. 남은 질량이 0.1 kg 이상이고 `floorInertia`(주관성 값을 1e-6 이상으로 올리고 삼각 부등식이 반올림으로 깨지면 작은 두 값을 같은 만큼 올림, 반올림 차는 대각 합의 1e-12배까지)로 고친 관성이 `isValidInertia`를 통과해야 쓴다. 아니면 기본 상자와 경고 `worldChassisMass`다. 읽는 중·못 읽은 메시가 섀시 쪽에 남았으면(관절 몸체의 것은 그 관절이 알림) 경고 `worldChassisMassPending`이다. 질량을 셀 수 있는 형상이 하나도 없어 질량 모델이 외곽 상자로 대신한 로봇(`defaultMass`)은 정해진 대체값이라 알리지 않는다(Rigidbody 카드가 알린다). 바퀴가 없는 로봇은 기저가 고정이라 섀시 몸체를 쓰지 않으며 기본 상자로 대신해도 알리지 않는다.

## 5. 구동 좌표와 모터 연결(`PhysicsWorld` 생성자)

### 5.1 좌표 순서

`Articulation`의 좌표 z는 다음 순서다: ① 기저 셋(필드 X, 필드 Y, 요; 바퀴가 있을 때만) ② 세계 설명 관절의 좌표(모터 구동 관절은 φ, 다단 리깅은 3b §8.1) ③ 관절에 묶이지 않은 `free` 좌표(`options.free`의 순서). `free`의 순서는 `spec.motors` 순서로 관절 모터가 아닌 모터마다 하나, 그 뒤에 `spec.wheels` 순서로 구동하지 않는 바퀴마다 하나다.

### 5.2 armature(좌표의 회전자·바퀴 반사 관성)

```
free 모터(관절 모터가 아님):  armature = J_rotor·G² + Σ_{w.motor = 이 모터} J_wheel(w) / G_ext(w)²         (G = params.gearbox, G_ext = 바퀴 외부 감속비)
구동하지 않는 바퀴:           armature = J_wheel(w)
질량 행렬:                    M_z = Sᵀ·M_q·S + diag(armature_c + MIN_COORDINATE_INERTIA)
```

체인(한 모터가 바퀴 셋을 구동하는 6륜 등)은 같은 좌표에 행이 여럿 걸리고 바퀴 관성이 모두 더해진다. 바퀴도 관절도 구동하지 않는 모터(인테이크 등)는 Σ가 비어 회전자 J_rotor·G²만 가진 좌표다(CLAUDE.md: armature만 있는 좌표, 부하 없음). 관절 모터 장치는 같은 `DcGearMotor`·관절 좌표를 공유한다(3b §9.1). `Articulation` 생성자는 `free`의 각 값을 좌표 armature로 받아 `armature_c`에 넣는다(기저 좌표 셋의 armature는 0).

### 5.3 바퀴 접촉 상수(`wheelContact`)

| 필드               | 값                                                                              |
| ------------------ | ------------------------------------------------------------------------------- |
| `coordinate`       | 구동 바퀴: 모터의 좌표, 구동하지 않는 바퀴: 자기 free 좌표                      |
| `rollPerRad`       | 구동 바퀴 `r / G_ext`, 구동하지 않는 바퀴 `r`(바퀴 좌표 1 rad당 바퀴 면 이동 m) |
| `traction`         | `tractionDirection(spec)`(§6.1)                                                 |
| `tractionFriction` | 메카넘 `μ_r = mecanumRollerFriction(μ, c_r)`, 그 밖 `μ`                         |
| `rollerScale`      | 일반 바퀴 1(쓰지 않음), 그 밖 `rollerResistanceScale(kind, μ)`                  |

### 5.4 구동 힘 조립(`driveForces`)에서 바퀴와 관련된 부분

- 모터마다(3b §5.4): `force += terms.force`, `damping += terms.damping + G²·viscous`, 기어 손실·모터축 쿨롱 상자를 `boxLo`·`boxHi`에 더한다. 식: `torque = terms.force − terms.damping·ω`, `loss = (1 − η)·abs(torque)`, `coulomb = G·τ_c`(G = `dc.gearbox`, η = `dc.efficiency`, τ_c = `dc.coulomb` = 데이터시트 역구동 마찰, 시험 기준 모터 2.3e-3 N·m), `boxLo −= coulomb + (torque > 0 ? loss : 0)`, `boxHi += coulomb + (torque < 0 ? loss : 0)`(모터가 미는 쪽으로 움직임을 막는 한쪽 상자).
- 바퀴마다 같은 좌표의 상자에 굴림 저항·베어링 마찰(§7)을 더한다: `boxLo −= f`, `boxHi += f`.
- 하중 N은 같은 하위 단계에서 `contacts()`가 먼저 정한 값이다(§12.3).
- 팀 코드가 보는 속도 제어(RUN_USING_ENCODER)·위치 제어는 모터마다 허브 펌웨어 제어(`HubMotorController`, 3b §6)를 거치며 바퀴 모터도 같다(T11).

### 5.5 최고 속도 표시값

`wheelTopSpeed = freeSpeed(출력축 데이터시트 무부하 속도, rad/s, 실제 감속비·덮어쓰기 반영) × (V_배터리 / 12) × r / G_ext`(m/s). 세계 설명의 바퀴 모터가 쓰는 값과 같고 엔코더의 SDK maxRPM이 아니다. 메카넘도 이상적인 IK에서 앞·옆 최고 속도가 바퀴 표면 속도와 같다(롤러 점성·굴림 저항은 빼지 않은 무부하 값). 기준 로봇(goBILDA 312 RPM 19.2:1, r = 0.052 m, 12 V)은 1.699 m/s(계산값: 32.6726 rad/s × 0.052), Pedro 기준 로봇(13.7:1)은 2.369 m/s(계산값)다.

## 6. 바퀴–타일 접촉 행(`contact.ts` `wheelRows`)

정확한 쿨롱 마찰이다: 법선 하중 N_i를 먼저 정하고 그 하중으로 상자를 정한다(미끄럼 곡선·벌점·정칙화 마찰 없음, 정지 = 운동). 그래서 정상 상태 미끄럼은 0이다. 행은 `Articulation`의 상자 LCP에 들어가고(3b §8.6) 목표 0, 충격 상자 [−b, +b]다(b는 힘 상자 × h). 하중이 0 이하(`!(N > 0)`)인 바퀴는 행도 점성도 넣지 않는다.

### 6.1 견인 방향 `tractionDirection`

```
메카넘: angle' = angle − π/4 (rollers = 'flbr'),  angle + π/4 (rollers = 'frbl')      → a = (cos angle', sin angle')
옴니·일반: a = u = (cos angle, sin angle)
```

롤러 형: `flbr` = 앞왼쪽·뒤오른쪽 자리의 바퀴(위에서 볼 때 롤러가 X를 이루는 표준 배치), `frbl` = 앞오른쪽·뒤왼쪽 자리. 코드는 `rollers === 'frbl'`일 때만 +π/4를 쓰므로 롤러를 모르는 입력(`null`, 인스펙터 카드 계산 등)은 `flbr`(−π/4)와 같다. 자유 롤러는 축 둘레 모멘트를 받지 못하므로 접촉력의 수평 성분이 땅에 닿은 롤러 축과 평행하다(method §4.1).

롤러 자유 방향·벽 접선·`wheelForwardTraction`에 쓰는 ẑ × d는 `perpendicular(d) = (−d.y, d.x)`(반시계 90°, `contact.ts`가 내보내 `fieldContact.ts`도 같이 쓴다)다. 롤러 저항 기본값 묶음은 `ROLLER_RESISTANCE = { viscous: ROLLER_VISCOUS, coulomb: ROLLER_COULOMB }`(`contact.ts`)이고 `wheelRows`의 `roller` 인자(`PhysicsWorldOptions.rollerViscous`·`rollerCoulomb`가 시험·맞춤에서 덮어씀)와 `wheelContact`의 `rollerCoulomb` 인자(메카넘 견인 계수 μ_r 계산에도 같은 값)로 바꾼다.

### 6.2 행 종류

| 바퀴 종류 | 행                  | 방향 d                            | 힘 상자(N)                   | 충격 상자       | 키                  | 비고                                                                                 |
| --------- | ------------------- | --------------------------------- | ---------------------------- | --------------- | ------------------- | ------------------------------------------------------------------------------------ |
| 메카넘    | 롤러 축 견인        | a = `tractionDirection`           | ±μ_r·N                       | ±h·μ_r·N        | `w{i}a`             | μ_r = √2·μ − k·c_r                                                                   |
| 메카넘    | 롤러 자유 방향 쿨롱 | ẑ × a(반시계 90°)                 | ±k·c_r·N                     | ±h·k·c_r·N      | `w{i}f`             | c_r = 0.076                                                                          |
| 메카넘    | 롤러 자유 방향 점성 | ẑ × a                             | 힘 −k·c_v·N·g_f              | (감쇠항)        | -                   | 행이 아니라 `damping` 목록 {j, c = k·c_v·N}. 암시로 M̂에 `h·c·Jᵀ J`를 더함            |
| 옴니      | 굴림 견인           | u                                 | ±μ·N                         | ±h·μ·N          | `w{i}a`             |                                                                                      |

점성 행의 직진 동작: 메카넘 직진에서는 자유 방향 미끄럼 g_f = 0이라 손실이 없다. 점성 감쇠는 `Articulation.step`에서 `baseDamping[a][b] += c·j[a]·j[b]`로 더해져 `M̂ = M + h·(D + 행 감쇠) + h²·K`에 들어간다.

### 6.3 일반 바퀴의 팔각형 마찰 원 근사

일반 바퀴의 마찰 원(반지름 μ·N)을 고정 팔각형으로 근사한다: u 기준 0°·45°·90°·135° 행 넷, 상자마다 ±h·μ·N / OCTAGON_DIVISOR.

```
OCTAGON_DIVISOR = 2·(cos 22.5° + sin 22.5°) = 2.613126   (계산값)
```

네 방향 상자의 합(민코프스키 합 = 지지 함수)이 22.5°에서 가장 크고 2.6131·b다. 그래서 b = μN/2.6131이면 합이 마찰 원에 내접(늘 원 안쪽)한다. 굴림·옆 방향(0°·90°)의 지지는 b·(1 + 2·cos 45°) = 2.4142·b = cos 22.5° · μN = 0.92388·μN(계산값)이라 원 안 7.6 %이고(가정 μ의 불확실성보다 작다고 코드가 적음), 반복 없이 결정적이다. 4륜 탱크의 제자리 회전·미끄러지는 동안 가속 = cos 22.5°·μ·g(T2b)가 이 근사의 결과다.

### 6.4 행 순서

`wheelRows`는 `spec.wheels` 순서로 바퀴마다 행을 낸다(메카넘·옴니: 견인 행 → 쿨롱 행, 일반: o0–o3). `PhysicsWorld.contacts`가 그 뒤에 벽 행(§11), 시즌 구조물 행(4ab), 몸체 충돌 행(5), 경기 요소 행(6a)을 이 순서로 붙인다. LCP 주축 선택과 기준 해시가 이 순서에 묶여 있다.

## 7. 굴림 저항·베어링 마찰(바퀴 좌표 상자)

굴림 저항은 바퀴 좌표의 쿨롱 상자다(성분 하나인 행이라 정지한 바퀴의 엔코더가 깜빡이지 않는다). `wheelCoordinateFriction`(좌표 단위 힘, N·m):

```
rolling = c_rr · N · rollPerRad          (N > 0일 때만, 아니면 0)
구동 바퀴:         f = rolling
구동하지 않는 바퀴: f = rolling + WHEEL_BEARING_FRICTION
boxLo[좌표] −= f,   boxHi[좌표] += f     (같은 좌표의 다른 상자와 합쳐 한 행: 모터 기어 손실·모터축 쿨롱 G·τ_c 포함)
```

- c_rr = `ROLLING_RESISTANCE` 0.087(§3.2), `PhysicsWorldOptions.rollingResistance`로 시험·맞춤 때만 덮어쓴다.
- 구동 바퀴의 `rollPerRad = r/G_ext`이므로 이 상자는 바퀴 면의 힘 c_rr·N을 모터 출력축 토크로 옮긴 것이다. 구동하지 않는 바퀴(`rollPerRad = r`)는 베어링 마찰 0.002 N·m를 더한다.
- 같은 방향 행은 `frictionRows`가 하나로 합친다(키 `f<좌표>`, 상자 = h × (boxLo, boxHi)).
- 데드휠 포드 끌림도 이 값에 섞여 있다(데드휠 포드 끌림·바퀴별 높이는 따로 모델링하지 않음, §20).

기준 로봇(13.6 kg, 무게중심 중앙, 바퀴 4)의 바퀴당 계산값: N = W/4 = 33.343 N(W = 133.370 N), 굴림 저항 힘 c_rr·N = 2.901 N, 메카넘 견인 행 상한 μ_r·N = 25.76 N, 롤러 쿨롱 상한 c_r·N = 2.534 N, 롤러 점성 계수 c_v·N = 1.267 N·s/m, 앞으로 끌 때 겉보기 한계 μ·N = 20.01 N(모두 계산값). 정지 출발에서 바퀴 힘 τ_s/r ≈ 46 N(19.2:1, 계산값 45.83 N)가 견인 한계 μ·N ≈ 20 N보다 커서 처음부터 미끄러진다(T2 주석).

## 8. 견인 한계 `wheelForwardTraction`과 인스펙터 계산값

### 8.1 `wheelForwardTraction(kind, angle, rollers, friction)`

바퀴 하나가 로봇 +X(앞)로 미는 견인 한계(하중 1 N당 N)다. `wheelRows`의 행 그대로(행 d마다 상자 계수 b)이며 인스펙터 로봇 카드의 견인 한계 가속이 이것을 쓴다.

```
메카넘: 행 = (a, b = μ_r),  (ẑ × a, b = k·c_r)
옴니:   행 = (u, b = μ),    (ẑ × u, b = k·c_r)
일반:   행 = 팔각형 넷(각 b = μ / 2.6131)
각 행 d: coupling = d·u.   |coupling| < 1e-9 이면 "수직"(팔각형 90° 행의 cos·sin 반올림 1e-16을 수직으로 봄): drag += b·abs(d.x)
                          아니면 "묶인": push += sign(coupling)·b·d.x
견인 = max(0, abs(push) − drag)
```

바퀴가 헛돌며 미는 동안 굴림과 묶인 행은 미끄럼 방향이 바퀴 회전으로 정해져 힘이 s·sign(d·u)·b·d이고(s = 회전 방향, 앞으로 미는 쪽을 고름), 굴림과 수직인 행은 바퀴 회전이 미끄럼을 만들지 않아 차대가 앞으로 움직이면 b·abs(d.x)만큼 거스른다. 롤러 점성은 미끄럼 속도에 따라 달라 넣지 않는다(정지에서 미끄러지기 시작할 때의 값).

| 바퀴                             | 결과                                                                                      | 계산값(기본 μ) |
| -------------------------------- | ----------------------------------------------------------------------------------------- | -------------- |
| 표준 메카넘(angle 0, 두 롤러 형) | μ 그대로(μ_r + k·c_r)·cos 45° = μ                                                         | 0.6            |
| 일반 바퀴 angle 0                | cos 22.5°·μ                                                                               | 0.9 → 0.83149  |
| X 드라이브 옴니(±45°)            | (μ − k·c_r)·cos 45°                                                                       | 0.8 → 0.51195  |
| H 드라이브 옆 바퀴(굴림 90°)     | 0(앞으로 밀지 못함. 거스르는 끌림은 굴림 저항·구동하지 않는 바퀴처럼 이 추정에 넣지 않음) | 0              |

### 8.2 인스펙터 로봇 카드·바퀴 카드의 계산

| 정지 하중 N_i             | 질량 모델의 로봇 질량 m·무게중심(편집 자세)이 거는 렌치 F_z = m·g, M_x = F_z·y_c, M_y = −F_z·x_c를 `distributeWheelLoads`(시뮬레이터와 같은 분배)로 나눔. 로봇 질량을 모르면 null                                                                                  |
| 견인 한계(바퀴 카드)      | μ·N_i(잠근 바퀴를 끄는 힘)                                                                                                                                                                                                                                         |
| 견인 한계 가속(로봇 카드) | `a_traction = g · Σ_구동 N_i·t_i / W`(t_i = `wheelForwardTraction`, 구동하는 바퀴만, W = m·g). 굴림 0°의 메카넘이 모두 구동하면 바퀴 μ의 하중 가중 평균 × g, X 드라이브 옴니는 약 0.64배, H 드라이브 옆 바퀴는 0. 로봇 질량을 모르거나 구동하는 바퀴가 없으면 null |
| 바퀴 질량·회전 관성       | §4.4의 도는 질량을 `effectiveWheelMass`로 자른 값과 `wheelSpinInertia`                                                                                                                                                                                             |
| 최고 속도 범위            | 구동하는 바퀴들의 `wheelTopSpeed`의 최소·최대                                                                                                                                                                                                                      |

바퀴 카드 보조 규칙(`wheelCardModel.ts`, `scene/wheel.ts`):

- 마찰 칸(겉보기 μ): 글자는 소수 둘(`formatWheelFriction`), 입력은 0(비운 것과 같음 = 종류 기본)이거나 0.05–3(`MIN_`·`MAX_WHEEL_FRICTION`) 안의 수만 받고 범위 밖은 `null`이라 칸이 틀렸다고 보이며 값은 그대로다(`sanitizeWheel`처럼 조용히 기본으로 돌리지 않는다). 계산값 줄은 `friction = effectiveWheelFriction`, 견인 한계 `tractionLimit = friction·load`.
- 종류를 바꿀 때(`wheelKindPatch`): 지름이 이전 종류의 기본값 그대로면 새 종류의 기본값(메카넘 0.104 m, 옴니·일반 0.096 m)으로 같이 바꾸고, 고친 지름은 그대로 둔다. 새 바퀴(`newWheel`)는 그 오브젝트(와 하위)에 모터가 하나뿐일 때만 그 모터를 구동 모터로 제안한다.
- [파트 크기로](`suggestWheelDiameter`): 오브젝트(그룹이면 하위) CAD 메시 경계 상자를 로봇 축으로 잰 높이(Z)를 `MIN_WHEEL_DIAMETER`–`MAX_WHEEL_DIAMETER`(0.005–1 m)로 자른 값이다(바퀴 축이 수평이라 바퀴가 어느 쪽을 향해도 높이가 지름). 형상이 아직 없거나 높이가 0이면 `null`.
- 계산 입력 가정: 정지 하중 렌치는 편집 자세 질량 모델이고(`robotStaticLoads`), 로봇 질량이 0이거나 바퀴가 없으면 `null`이다.

## 9. 법선 하중 분배(`wheelLoads.ts` `distributeWheelLoads`)

바닥이 받쳐야 할 렌치(로봇 좌표 원점 = 로봇 중심 바닥 기준 수직 힘 F_z와 롤·피치 모멘트 M_x·M_y)를 바퀴 접점 하중 N_i ≥ 0으로 나눈다. 시뮬레이터(하위 단계마다)와 인스펙터 바퀴 카드(정적 하중)가 같이 쓴다.

### 9.1 식

```
ΣN_i = F_z
Σ y_i·N_i = M_x
−Σ x_i·N_i = M_y                (r_i × N_i·ẑ = (y_i·N_i, −x_i·N_i, 0))
행렬: A = [[1, y_i, −x_i]] (바퀴 i마다 한 열), d = (F_z, M_x, M_y), A·N = d
```

바퀴가 넷 이상이면 부정정이다. 같은 강성 스프링(폼 타일) 위의 강체 차대로 보면 처짐이 평면이라 N이 A의 행 공간에 있고, 그 해는 최소 노름 해 하나다(method §5.2):

```
N = Aᵀ (A Aᵀ)⁺ d                   (구현: M = Σ_{활성 바퀴} a_i a_iᵀ, w = M⁺ d, N_i = w0 + w1·y_i − w2·x_i)
```

정사각 닫힌 꼴(바퀴가 (±a, ±b), 정지, 무게중심 (x_c, y_c)): `N_i = (W/4)(1 + x_c·x_i/a² + y_c·y_i/b²)`(시험이 확인). 동적 하중 이동(일정 가속 a, 무게중심 높이 h, 앞뒤 바퀴 간격 L = 2·LX): 앞바퀴 합의 변화 = −m·a·h/L(T5b, 2 % 이내).

ZMP(영 모멘트점): `x_z = −M_y / F_z`, `y_z = M_x / F_z`.

### 9.2 알고리즘(순서와 문턱)

1. `F_z ≤ 0`이거나 바퀴가 없거나 M_x·M_y가 유한하지 않으면 모두 0, `unsupported` 0(들린 로봇: 평면 모델에서는 생기지 않음).
2. 접점의 볼록 껍질(`convexHull`): Andrew 단조 사슬, 반시계, 정렬 기준 x → y → 원래 순번(결정적), 같은 점·일직선 점 제외(외적 ≤ 0이면 꼭짓점을 뺌), 고유점 2개 이하면 그대로, 모두 일직선이면 양 끝 두 점.
3. ZMP를 껍질로 옮긴다(`closestInHull`): 껍질(꼭짓점 3개 이상)의 모든 변 a→b에서 `cross(a, b, p) ≥ −HULL_EPSILON·abs(변)`(HULL_EPSILON = 1e-9 m, 반올림 잡음)이면 안, 아니면 가장 가까운 변 위의 점. 꼭짓점 1개면 그 점, 2개면 그 선분.
4. `unsupported = F_z · 거리(ZMP, 옮긴 점)`(받쳐지지 않은 모멘트, N·m). 시뮬레이터는 평면이라 넘어지지 않고 알림만 낸다.
5. `d = (F_z, F_z·z_y, −F_z·z_x)`(z = 옮긴 점)로 최소 노름 해를 푼다. `pseudoInverse3`(Jacobi 고유 분해, 가장 큰 고유값의 1e-9배 이하는 버림, §14.2).
6. 활성 집합: 활성 바퀴의 하중 중 `N < −1e-12·F_z`인 것 가운데 가장 작은 것(같으면 작은 순번)을 비활성으로 빼고 다시 푼다. 바퀴 수만큼만 되풀이한다(결정적). 뺀 바퀴는 하중 0(뜬다). 마지막에 `max(0, N)`.
7. 잔차 `abs(ΣN − F_z) + hypot(Σy·N − d1, −Σx·N − d2) > 1e-9·F_z·(1 + hypot(z_x, z_y))`이면(남은 바퀴의 껍질이 z를 품지 않아 활성 집합이 받쳐지는 해를 못 찾은 경우) 껍질 부채꼴 삼각형 무게(`hullWeights`)로 대체한다: 껍질 꼭짓점 1개면 그 바퀴에 F_z, 2개면 선분 보간 `t = clamp(((z − a)·(b − a))/abs(b − a)², 0, 1)`로 a 바퀴에 (1 − t)·F_z, b 바퀴에 t·F_z, 3개 이상이면 껍질 꼭짓점 0번을 공유하는 부채꼴 삼각형 중 z를 품은 것(바리센트릭 가중치 ≥ −1e-9, 마지막 삼각형은 무조건)의 가중치를 `max(0, w)`로 자르고 합으로 나눠 F_z를 나눈다. 껍질 꼭짓점 → 바퀴 순번은 좌표가 같은 첫 바퀴.

### 9.2.1 시험이 고정한 예(`wheelLoads.test.ts`, 정사각 4륜 a = b = 0.168 m, W = 13.6·g)

| 경우                                                     | 결과                                                                     |
| -------------------------------------------------------- | ------------------------------------------------------------------------ |

| 13.6 kg, 무게중심 6 cm 앞(method §5.3 예)                | 앞 45.25 N, 뒤 21.43 N                                                   |

## 10. 기저 렌치·하중 필터·받침 알림

### 10.1 기저 렌치(`Articulation.baseWrench`)

바닥이 받쳐야 할 (F_z, M_x, M_y)를 섀시 관절의 RNEA 공간 힘에서 얻는다. 섀시 관절(나무 순번 BASE_JOINTS − 1)이 자식(관절 몸체 포함)을 모두 더한 공간 힘 f = [n_O; f](필드 원점 기준)을 로봇 원점 P(섀시 원점)로 옮기고 로봇 축으로 돌린다.

```
n_P = n_O − P × f                 (P = 섀시 원점, 필드 좌표)
(M_x, M_y) = (Rᵀ n_P)의 x·y 성분   (R = 섀시 회전: 로봇 축)
F_z = f의 z 성분
```

RNEA는 q̈ 자리에 **걸러진 가속**을 넣고 중력을 고정 기저의 위쪽 g 가속으로 준다(3b §8.4). 중력·위치 q·속도 q̇는 지금 값이다. 바퀴 마찰·벽 힘은 바닥 높이의 수평 힘이라 P 둘레에 z 모멘트만 내므로 (F_z, M_x, M_y)는 바퀴 법선 하중만 받친다(method §5.1). 기저가 없으면 null.

### 10.2 가속 저역 통과(`LOAD_FILTER_TAU`)

```
α = 1 − exp(−h / τ)                         τ = LOAD_FILTER_TAU
filteredAccel_c ← filteredAccel_c + α · ((v⁺_c − v_c)/h − filteredAccel_c)         (좌표마다, 하위 단계마다)
```

| 항목                       | 값   | 단위 | 위치                             | 상태·근거                                                                                                                                                                                                                                   |
| -------------------------- | ---- | ---- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 하중 이동 필터 시간 상수 τ | 0.02 | s    | `wheelData.ts` `LOAD_FILTER_TAU` | [가정: 폼 타일·차대 피치 순응(Unity WheelCollider 서스펜션 스프링·댐퍼의 역할). 벽 충돌·관절 한계 충격이 한 하위 단계 동안 수천 N의 하중 이동을 만들지 않게 한다(비평 §2.8)]. 재기 어렵다(바퀴 하중을 재는 힘 판 필요), 수치 안정이 주 목적 |

h = 1 ms이면 α = 0.048771(계산값). `Articulation`은 `offset > 0`(기저 있음)이고 τ > 0일 때만 갱신한다. 높은 무게중심(0.5 m)·μ 1.0의 1.6 m/s BRAKE 정지에서도 뒷바퀴 하중이 하위 단계마다 번갈아 뛰지 않는다(T15).

### 10.3 받침 알림(`SupportMonitor`, 실행마다 한 번)

```
lifted  = F_z > 0 이고 어떤 바퀴의 N ≤ F_z·1e-9        (껍질 대체 경로·반올림 잡음도 0으로 봄)
tipping = F_z > 0 이고 unsupported > F_z · TIPPING_ARM
liftTime ← lifted ? liftTime + h : 0;     tipTime ← tipping ? tipTime + h : 0
알림 조건: 시간 ≥ SUPPORT_NOTICE_DELAY − h/2          (0.1 s를 1 ms 하위 단계로 더하면 0.09999…라 하위 단계 절반 여유)
```

| 항목                    | 값   | 단위 | 위치                                  | 상태·근거                                                                                                   |
| ----------------------- | ---- | ---- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 알림 지연               | 0.1  | s    | `wheelData.ts` `SUPPORT_NOTICE_DELAY` | [가정: 급정거 한 번마다 알리지 않게]. 재지 않음(알림 문턱)                                                  |
| 넘어짐 팔 `TIPPING_ARM` | 1e-3 | m    | `contact.ts` `TIPPING_ARM`            | [가정: ZMP가 바퀴 껍질 밖으로 1 mm(반올림 잡음보다 훨씬 크고 넘어짐을 놓치지 않을 만큼 작다, spec-3c §1.4)] |

알림 코드 `tipping`·`wheelLift`는 params 없음이고 `world.ts` `notify`가 같은 (code, params)를 한 번만 낸다. 넘어지지는 않는다(알림만). 시험: 무게중심 앞 7.5 cm·높이 0.3 m·μ 2에서 전출력 BRAKE 정지는 약 6 m/s²로 서서 ZMP = 0.075 + 0.3·a/g ≈ 0.27 m가 앞바퀴(0.15 m) 밖이라 0.1 s 뒤 `tipping`·`wheelLift`를 한 번씩 알린다(T5c). 벽에 1.6 m/s로 박아도 거짓 알림이 없다(T14, 걸러진 가속).

## 11. 벽 접촉 행(`wallRows`)과 `blocked`

평면 경로(세계 설명에 섀시 충돌 형상 `robot.colliders`가 없을 때)에서만 쓴다. INIT의 실제 실행은 섀시가 3D 충돌 경로(5)라 이 행이 없고 `bodyCollision.ts`가 맡는다. 시즌 구조물 행(`structureRows`)은 이 행 뒤에 붙으며 `field-biobuzz.md` §13에 있다.

### 11.1 행

외곽 꼭짓점 k(로봇 좌표를 yaw로 돌린 오프셋 r_k)와 벽 w(`+x`, `−x`, `+y`, `−y` 순서)마다:

```
position = pose.x + r_k.x   (벽이 x축) 또는 pose.y + r_k.y (y축)
gap      = innerHalf − sign_w · position                     (sign: +x·+y는 +1, −x·−y는 −1)
speed    = (x축) vx − ω·r_k.y,  (y축) vy + ω·r_k.x          (접근 속도)
근방 조건: gap ≤ abs(speed)·h + WALL_MARGIN                  (아니면 행을 넣지 않음)
안쪽 법선 n = −sign_w · e_축,   접선 t = ẑ × n
J(d) = [d.x, d.y, −d.x·r_k.y + d.y·r_k.x, 0, …]            (바퀴 좌표 성분 없음)
법선 행: 키 n{벽}{k}, J(n), 목표 −max(gap, 0)/h, λ ∈ [0, ∞)
접선 행: 키 t{벽}{k}, J(t), 목표 0, 상자 = WALL_FRICTION · max(0, λ_n)
```

- 법선 행은 한쪽(λ ≥ 0)이고 J_n·v⁺ ≥ −max(gap, 0)/h라 이미 걸쳐 있으면 밀어내지 않는다(반발 0, 위치 자르기 없음). 걸친 시작 시험: 꼭짓점 1 cm 침투 정지 시 자세 변화 < 1e-9 m, 밀어도 침투 증가 < 1e-6 m(T6c).
- 접선 마찰의 상자는 법선 충격에 기대므로 `Articulation`이 **고정 2회 엇갈림**으로 푼다: 1회차의 법선 충격은 앞 하위 단계의 같은 키 충격 × h/lastH, 2회차는 1회차 값(3b §8.5 8번). 상자가 0이면 행을 넣지 않는다.
- 벽 힘은 바닥 높이에 작용한다고 본다(하중 이동 없음, 한계).
- 벽 반폭 `innerHalf`는 시즌 FieldSpec `perimeter.innerHalf`다(`PhysicsWorld`가 `fieldCollision(...).innerHalf`로 넘김). 'none' 시즌은 `field.ts`의 `WALL_INNER_HALF` = `FIELD_SIZE/2 − WALL_THICKNESS/2`(FIELD_SIZE = 144 in = 3.6576 m, WALL_THICKNESS 0.025 m, 높이 `WALL_HEIGHT` 0.3 m, 안쪽 반폭 1.8163 m(계산값))와 같은 double이라 3c와 바이트까지 같다. BIOBUZZ의 안쪽 반폭은 1.79286 m(`field-biobuzz.md`).

### 11.2 상수

| 항목                          | 값   | 단위 | 위치                           | 상태·근거                                                  |
| ----------------------------- | ---- | ---- | ------------------------------ | ---------------------------------------------------------- |
| 벽 행 근방 여유 `WALL_MARGIN` | 1e-3 | m    | `contact.ts` `WALL_MARGIN`     | [가정: 3b 관절 한계 근방(`LIMIT_MARGIN` 1 mm)과 같은 크기] |
| 벽 마찰                       | 0.4  | -    | `wheelData.ts` `WALL_FRICTION` | §3.2                                                       |

### 11.3 `blocked`

`blocked`는 틱 안 어느 하위 단계든 섀시–정적 법선 행의 충격 λ_n > 0이다. 평면 경로는 `isBlockingNormal(row) = friction이 없고 hi = ∞`인 행(벽·구조물 법선 행)이고, 3D 경로는 `bodyCollision.ts`의 `rows`가 돌려주는 `blocking`(섀시–정적 짝 `chassisStatic`의 법선 행, 키 `cn.rk…/w…`·`cn.rk…/s…`)이다. 관절 몸체·자기 충돌·공 행은 세지 않는다. 막힌 동안 실제 자세를 따르는 데드휠·IMU·Pinpoint·OTOS는 멈추고, 바퀴 엔코더는 모터가 견인 한계를 넘으면 헛돌며 늘고 아니면 모터가 막혀 멈춘다(T6b: 전출력이면 엔코더가 계속 늘고 데드휠은 0, power 0.3이면 엔코더가 서고 전류 = 0.3·정지 전류).

벽을 옆으로 미는 정지 문턱은 바퀴 좌표의 정적 손실 상자(기어 손실·모터 쿨롱·굴림 저항) 때문에 μ_w보다 크다(T6: 옆/앞 힘 비가 벽 μ 0.4보다 작은 0.15/0.6이면 안 미끄러지고, 0.5/0.6이면 미끄러짐). 벽 밀기 경계 해석식(T17): 막힌 바퀴가 미끄러지기 시작하는 힘 `(τ_stall·d·V/12 − G·τ_c)/r − c_rr·N`(d = power), 메카넘 한 바퀴가 앞으로 내는 견인 한계 μ·N, N = W/4. power 0.5에서 문턱 μ가 0.5–0.8 사이이고 문턱 ∓0.05에서 갈린다.

바퀴가 하나라도 있으면 관절 나무 앞에 가상 관절 셋을 둔다(`BASE_JOINTS` = 3):

| 순번 | 종류         | 축        | 원점                                    | 몸체                                       |
| ---- | ------------ | --------- | --------------------------------------- | ------------------------------------------ |
| 0    | 직선(필드 X) | (1, 0, 0) | (start.x, start.y, 0), 부모 −1          | 질량 0, 관성 0                             |

### 12.3 `substep` 한 번의 순서

1. 시각 t가 다음 제어 표본(`nextSample`) 이상이면 모든 모터 `controller.sample(...)`(허브 제어, 10 ms 격자: `HUB_CONTROL_PERIOD_NANOS` = 10 000 000 ns, `actuators.ts`). 표본을 뜬 뒤 `nextSample = (floor(t / 10 ms) + 1) × 10 ms`이고, 첫 `step`에서는 `nextSample = ceil(t / 10 ms) × 10 ms`로 잡는다. 표본이 받는 값: 사이드카 출력·PIDF, `position = floor(raw)`, `velocity` = 제어기 50 ms 창의 틱/s, RUN_TO_POSITION이면 `rawTarget = targetPosition + shaftOffset`.
2. 모터마다 전력단 상태 `controller.stage(out)`, duty × `forwardSign`.
3. 부유 기저면 `contacts(art, from, h)`:
   a. `wrench = art.baseWrench()` → `wheelLoads(wheels, wrench)` → `this.loads`(이번 하위 단계의 바퀴 하중, `supportLoads()`).
   b. `SupportMonitor.update` → `wheelLift`·`tipping` 알림.
   c. `wheelRows(wheels, loads, yaw, h, m, roller)`.
   d. 섀시가 3D 경로면(`spec.robot.colliders !== undefined`) 여기까지(바퀴 행만). 아니면 `wallRows` → `structureRows`를 붙임(`rows = [...wheel.rows, ...walls, ...structures]`, `damping = wheel.damping`).
   e. `blocking = rows.filter(isBlockingNormal)`.
4. 접촉 틀(`art.contactFrames()`)이 필요하면(몸체 충돌·공) 한 번 만들고, 몸체 충돌 행(5)과 공 행(6a)을 붙인다. 몸체 충돌 행이 던지면 `art.step`이 던진 것과 같은 실패 복구를 쓴다.
5. `art.step(h, driveForces, contacts)`: 구동 힘(모터 전기 토크·손실·점성, 바퀴 좌표 굴림 저항·베어링 상자, 서보)을 모으고 속도 암시 오일러 + 상자 LCP(엇갈림 2회) + 한계 충격으로 푼다.
6. 모터 raw 틱 갱신 `raw = forwardSign·ticksPerRad·z[좌표]`.
7. 기저가 from에서 to로 움직였으면 `moveRobot`(§13)로 오도메트리를 세고, 막힌 행(`blocking`)의 충격 `contactImpulse(key) > 0`이 하나라도 있으면 `blocked`.
8. 구간 끝(하위 단계 이후)에 모터 단자 전류 `current = abs(dc.current(stage, voltage, v[좌표]))`를 구한다.

### 12.4 풀이 실패

LCP가 풀리지 않거나(수렴 안 함 등, `Articulation`은 상태를 바꾸기 전에 던진다) 몸체 충돌 행이 던지면 그 하위 단계의 모든 속도를 0으로 하고 위치는 그대로 둔 채 다음 하위 단계에서 다시 푼다. `worldError`(같은 detail은 실행마다 한 번)로 알린다. 로봇 섬에 묶인 공도 속도 0이고 다른 공 섬은 그대로 푼다(6a).

## 13. 오도메트리·센서 입력과의 연결

기저가 한 하위 단계 동안 from에서 to로 움직이면 실제 변위(로봇 좌표 twist ξ = (dx, dy, dθ) = `twistBetween(from, to)`)로 오도메트리를 센다.

### 13.1 포드 이동과 틱

```
podTravel(ξ, p, 'forward') = dx − dθ·p.y            (p: 포드 접점, 로봇 좌표)
podTravel(ξ, p, 'strafe')  = dy + dθ·p.x
데드휠 raw += significant(podTravel · ticksPerMeter · (reversed ? −1 : 1))
significant(x) = abs(x) < POD_NOISE_TICKS ? 0 : x
```

| 항목                                    | 값   | 단위         | 위치       | 상태·근거                                                                                                                                                                             |
| --------------------------------------- | ---- | ------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 포드 증가 반올림 잡음 `POD_NOISE_TICKS` | 1e-9 | 틱/하위 단계 | `world.ts` | [가정: 동역학 풀이의 좌우 비대칭 반올림이 곧게 달리는 로봇에 1e-16 m 수준의 옆 이동을 남기는데 floor가 −1틱으로 세지 않게 한다. 1e-9틱/ms는 1e-6틱/s라 실제 이동으로는 보이지 않는다] |

일정한 변위 동안 점 p의 이동은 로봇 좌표에서 일정하다. 입력 position은 `floor(raw)`(원시 허브 틱), velocity는 허브 50 ms 측정(20의 배수, int16 감김은 사이드카가 처리). 데드휠과 포트를 함께 쓰는 모터의 position·velocity는 포드 값이다(실제 배선).

### 13.2 Pinpoint(펌웨어 흉내)

```
scale = podTicksPerMm · 1000                                   (틱/m)
encX += significant(podTravel(ξ, xPod, 'forward') · scale · (xReversed ? −1 : 1))
encY += significant(podTravel(ξ, yPod, 'strafe')  · scale · (yReversed ? −1 : 1))
podX = (floor(encX) − 이전 floor) · xSign / ticksPerMm   (mm, xSign: 팀이 쓴 xDirection REVERSED면 −1)
podY = (floor(encY) − 이전 floor) · ySign / ticksPerMm
dh = (yawTo − yawFrom)                                          (시작 요 기준 상대)
dx = podX + dh · xOffsetMm,   dy = podY − dh · yOffsetMm
mid = (h0 + h1)/2
x += dx·cos(mid) − dy·sin(mid),   y += dx·sin(mid) + dy·cos(mid)       (전원 켠 뒤 틀: X 앞·Y 왼쪽, mm)
```

팀이 해상도(`ticksPerMm`)를 아직 정하지 않았으면 x·y는 그대로 둔다. heading은 감지 않은 내장 IMU 요다(`yaw = poseNow.yaw − start.yaw`).

### 13.3 OTOS·IMU

- OTOS: 물리 센서 틀 `mount = (position, mountingAngle − π/2)`(SDK 샘플 축 X 오른쪽·Y 앞·반시계 +이 로봇 X 앞·Y 왼쪽에서 −90°), 팀 오프셋 O, 센서 자세 S(t) = compose(poseNow, mount)일 때 `raw = O ∘ (S(0)⁻¹ ∘ S(t)) ∘ O⁻¹`. 속도·가속도는 원시 틀에서 틱 사이 차이다. 가속도는 칩 레지스터 범위로 자른다: 선가속 ±16 g = ±156.906 m/s²(`OTOS_MAX_LINEAR_ACCEL = 16·GRAVITY`, 계산값), 각가속 ±1000π rad/s²(`OTOS_MAX_ANGULAR_ACCEL`) — 근거: SparkFun OTOS 드라이버의 int16 변환 MPSS_TO_INT16 = 32768/(16·9.80665), RPSS_TO_INT16 = 32768/(π·1000), 칩 흉내 `OtosChip.java`의 int16 포화(`sidecar/sdk/com/qualcomm/hardware/sparkfun/SparkFunOTOS.java`; 동역학에서는 벽 충돌 하위 단계에 수십 g가 나오므로 칩처럼 자른다, spec-3c §1.8).
- IMU: `yaw = wrapAngle(poseNow.yaw − start.yaw)`, `yawRate = 기저 ω`(바퀴 없으면 0), pitch·roll·그 속도는 0.

관절 하위의 IMU·OTOS·데드휠·Pinpoint는 섀시에 붙은 것으로 계산한다(3b 한계, 렌더러가 경고).

## 14. 운동학 오라클 `Drivetrain`과 SE(2)

2단계의 시뮬레이터였고 3c부터는 **시험 오라클**이다: 미끄럼 없는 정상 상태의 동역학 결과가 이 해와 같아야 한다(T0). 바퀴마다 굴림 변위 s_i(m, 앞으로 구르면 +)에서 로봇 좌표 변위(Δx, Δy, Δθ)를 최소제곱으로 구한다(미끄럼 허용, 질량 없음).

### 14.1 구속 행

바퀴 i의 굴림 단위 벡터 u_i, 구속 방향 a_i(그 방향으로는 미끄러지지 않는다). 행: `a_i · (v + ω ẑ × p_i) = s_i · (u_i · a_i)`.

| 바퀴   | 행(구동하는 바퀴)                                       | 구동하지 않는 바퀴 |
| ------ | ------------------------------------------------------- | ------------------ |
| 메카넘 | a = `tractionDirection`, 우변 계수 a·u(= cos 45°)       | 행 없음            |
| 옴니   | a = u, 계수 1                                           | 행 없음            |
| 일반   | a = u 행(계수 1)과 옆 행 (−u_y, u_x)(옆 변위 0, 계수 0) | 옆 행만            |

ω 성분은 바퀴들의 평균 반경 거리 L(바퀴 위치의 원점 거리 평균, 1e-6 m 이하면 1)로 척도를 맞춘다(ω·L, 단위가 m). 정규 방정식 AᵀA는 3×3이고 대칭 고유 분해(Jacobi)로 유사 역행렬을 만든다. 행이 없으면 움직이지 않는다.

표준 메카넘 역기구학(바퀴가 (±lx, ±ly), l = lx + ly): `v_fl = vx − vy − lω`, `v_fr = vx + vy + lω`, `v_bl = vx + vy − lω`, `v_br = vx − vy + lω`. 4륜 탱크(일반 바퀴) 제자리 회전: 바퀴 굴림 Δ(왼쪽 −Δ, 오른쪽 +Δ)에 대해 `ω = Δ·ly/(lx² + ly²)`(옆 미끄럼 저항과 앞뒤 미끄럼 저항이 같다고 본 쿨롱 마찰 균형과 같다). 6륜 드롭센터처럼 바퀴마다 하중이 다른 경우는 다루지 않는다(한계).

### 14.2 대칭 3×3 유사 역행렬·Jacobi 고유 분해

| 상수             | 값   | 위치            | 설명                                                                                                                                                                               |
| ---------------- | ---- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RANK_TOLERANCE` | 1e-9 | `drivetrain.ts` | 가장 큰 고유값의 이 배 이하인 고유값은 0으로 봄(여인수·행렬식 역행렬은 계수 1에서 행렬식이 반올림 잡음이라 쓰지 않음). 특이한 배치(바퀴 하나, 평행한 옴니)에서 최소 노름 해를 고름 |
| `MAX_SWEEPS`     | 50   | `drivetrain.ts` | 순환 Jacobi 회전의 최대 순회 수(3×3은 보통 5번 안에 비대각이 0). 출처 기록 없음                                                                                                    |

Jacobi 회전: 순회 4번 넘게 돈 뒤(`sweep > 3`)에는 대각에 견줘 `100·abs(a_pq)`가 반올림 아래인(`abs(a_pp) + g === abs(a_pp)`이고 `abs(a_qq) + g === abs(a_qq)`, `g = 100·abs(a_pq)`) 비대각을 0으로 둔다. 순회마다 쌍 (0,1)·(0,2)·(1,2) 순서로 돌고, 세 비대각이 모두 정확히 0이면 순회를 끝낸다(`MAX_SWEEPS` 50이 상한). 회전각은 `h = a_qq − a_pp`, `θ = h/(2·a_pq)`, `t = sign(θ)/(abs(θ) + sqrt(θ² + 1))`(abs(회전) ≤ 45°; θ = 0이면 +), `c = 1/sqrt(t²+1)`, `s = t·c`이다. `h`가 `a_pq`에 견줘 너무 커서 `abs(h) + g === abs(h)`이면 θ를 만들지 않고 `t = a_pq/h`로 쓴다. 갱신은 `a_pp −= t·a_pq`, `a_qq += t·a_pq`, 나머지 비대각 두 개와 고유 벡터 열 p·q를 (c, s)로 돌린다. 사칙연산과 제곱근만 써서 결정적이다. `pseudoInverse3`는 가장 큰 고유값이 0 이하(`!(max > 0)`)면 영행렬을 돌려준다. 질량 모델(렌더러)의 주관성 값과 세계 설명의 관성 검증(`isValidInertia`)도 이것을 쓴다.

### 14.3 SE(2)

로봇 좌표의 일정한 변위를 필드 자세에 적용 `applyTwist(P, ξ) = P ∘ exp(ξ)`와 두 자세 사이 변위 `twistBetween = log(P0⁻¹ ∘ P1)`(yaw는 감지 않은 차이):

```
a = sin(dθ)/dθ,  b = (1 − cos dθ)/dθ         (abs(dθ) < 1e-6이면 급수: a = 1 − dθ²/6,  b = dθ/2 − dθ·dθ²/24)
applyTwist:  t = (a·dx − b·dy, b·dx + a·dy),  P' = P + R(yaw)·t,  yaw' = yaw + dθ
twistBetween: t = R(−yaw0)·(P1 − P0),  det = a² + b²,  dx = (a·tx + b·ty)/det,  dy = (−b·tx + a·ty)/det
```

`compose(p, q) = p ∘ q`, `inverse(p)`, `wrapAngle`(−π, π]. 급수 전환 문턱 1e-6 rad은 출처 기록 없음.

### 15.2 측정 절차

`pedroVelocity(axis)`: 지정한 축(앞 `'x'`: 명령 mecanum(1, 0, 0), 왼쪽 옆걸음 `'y'`: mecanum(0, −1, 0))으로 power 1을 2 s 준 끝 속도(m/s)를 필드 대각선(π/4) 방향으로 마지막 10틱(50 ms) 평균으로 잰다. 한 번이라도 `blocked`면 던진다(벽에 닿으면 안 됨).

`pedroDeceleration(axis)`:

1. 1틱을 power 1로 돈다.
2. k = 1…1999: 한 틱씩 돌며 틱 (k−1, k) 사이 대각선 속도 `speed_k`를 잰다. 아직 끊지 않았다면 명령 그대로(power 1).
3. `speed_k > 0.762 m/s`(30 in/s)가 처음 되면 그 틱을 `cut`, `cutSpeed = speed_k`로 기억한다. 그 다음 틱부터 모든 모터를 `power 0 + zeroPower FLOAT`로 낸다.
4. 끊은 뒤 `speed_k ≤ 0.0254 m/s`(1 in/s)가 되면 `(cutSpeed − speed_k) / ((k − cut)·DT)`(DT = 5 ms)를 평균 감속(m/s², 양수)으로 돌려준다. 1999틱 안에 서지 않으면 던진다.

### 15.3 맞춤 순서(코드 주석)

1. 앞 감속은 굴림 저항만 정하므로 `ROLLING_RESISTANCE`를 먼저 맞춘다(목표 0.8795 m/s²).
2. 롤러 저항 둘(`ROLLER_VISCOUS`, `ROLLER_COULOMB`)로 옆/앞 속도 비(목표 0.80439)와 옆 감속(목표 1.9852 m/s²)을 맞춘다. 점성만으로는 비 0.804에서 옆 감속이 1.30 m/s²(목표보다 35 % 작음)라 쿨롱 상자를 더했다.
3. 결과(코드 주석): 앞 감속 0.879 m/s², 비 0.8043, 옆 감속 1.978 m/s²(셋 다 0.5 % 안). 현재 트리에서 다시 잰 값은 §3.5.

다른 로봇(팀 로봇)에 맞추려면: 팀 로봇에서 Pedro 튜너의 값(앞 FLOAT 감속, 옆 FLOAT 감속, 앞·옆 최고 속도)을 재고, `robotSpec`의 `Robot` 옵션을 그 로봇의 질량·감속비·바퀴로 바꾼 뒤 `PhysicsWorldOptions`로 세 계수를 바꿔 위 두 단계를 되풀이한다(assumptions.md "측정 방법").

### 15.4 시험 도구가 허브 출력을 만드는 규칙(`driveTestkit.ts`)

- `motorOut(device, power)`: 사이드카 허브 출력 하나. `mode` = RUN_WITHOUT_ENCODER, `power = power × HUB_SIGN × DIRECTION[device]`(팀 코드의 `setPower`를 인스펙터 방향 그대로 쓴 값을 허브 부호로 옮김, `HUB_SIGN` = 구성 태그 형식의 `rotationSign`), `velocity` null, `enabled` true, `zeroPower` BRAKE, `targetPosition` null, `encoderOffset` 0. 바꿀 키는 `change`로 덮어쓴다(FLOAT는 `zeroPower: 'FLOAT'`).
- `Runner.run(seconds, out)`: 틱 `k·tick`(기본 5 ms)마다 `world.step(k·tick, out(k))`를 부르고 틱마다 입력(`inputs`)·자세(`poses`)를 모은다. `Runner.speed(a, b, axis)`: 틱 a·b 사이 필드 축(`'x'`·`'y'` 또는 각 θ 방향) 평균 속도 = `(Δx·cos θ + Δy·sin θ) / ((b − a)·tick)`.
- 정상 로봇의 모터 값은 `datasheet(gearbox) = testMotorParams(TAG, gearbox)`, 이상 모터 판은 `ideal`(§15.1).

### 16.3 바퀴 위치·롤러 `auto`(렌더러 `robotWheels`)

- 바퀴 위치(`wheelPosition`): 보이는 형상이 있으면 그 피벗(CAD 파트는 경계 상자 중심), 없으면(그룹·형상 없는 어셈블리) 하위 형상 피벗들의 경계 상자 중심, 그것도 없으면 자기 피벗. 로봇 밖이면 null.
- 메카넘 롤러 `auto`: 메카넘 바퀴들의 중심(평균)에 대한 사분면. 앞왼(x > 0, y > 0)·뒤오른 → `flbr`, 앞오른·뒤왼 → `frbl`. 중심선 위(`ROLLER_POSITION_EPSILON` 5 mm 미만)거나 굴림 방향이 앞뒤(0°·180°의 `ROLLER_ANGLE_EPSILON` 1° 안)가 아니면 정할 수 없어 `flbr`와 경고 `worldRollersAmbiguous`. 180°로 굴리는 바퀴도 롤러 축이 같아서 같은 형이다. 두 상수는 출처 기록 없음.
- 바퀴 오브젝트의 조건(`canHaveWheel`): 로봇·CAD 루트에는 두지 않고(CAD 루트 transform은 정렬), 관절이 있는 오브젝트에도 두지 않는다(바퀴는 로봇 몸체에 붙은 것으로 계산). 바퀴를 구동하는 모터는 관절 구동에 쓰지 않는다.
- 구동 모터는 같은 로봇의 motor 컴포넌트다. 모터가 없으면 `worldWheelNoMotor`, 지웠거나 다른 로봇의 것이면 `worldWheelMotorMissing`이고 그 바퀴는 따라 구르기만 한다. 바퀴 설정 모터가 둘 이상의 바퀴에 같으면 체인이다.

### 16.4 외곽·높이(`robotOutline`)

로봇의 CAD 루트들의 경계 상자(`cad.bounds`, CAD 좌표) 8꼭짓점을 로봇 좌표로 옮겨 바닥 사각형(반시계)과 꼭짓점 z의 최대값을 낸다. CAD 루트의 피벗은 경계 상자 중심이라 꼭짓점의 로컬 좌표는 꼭짓점 − 중심이다. CAD가 없으면(또는 폭이 0이면) 18 in 정사각형(`ROBOT_SIZE` = 18 in = 0.4572 m, 반폭 0.2286 m)이고, 높이가 `MIN_OUTLINE_HEIGHT` 1 mm 이하(CAD 없음 포함)면 18 in(0.4572 m)다 [가정: 높이는 편집 자세 CAD 최대 z, 없으면 18 in]. 관절로 올라간 높이는 넣지 않는다(편집 자세). 형상 로딩과 관계없다. 꼭짓점 순서: (maxX, minY), (maxX, maxY), (minX, maxY), (minX, minY).

### 16.4.1 받침 다각형 검사(`fewWheelContacts`)

서로 다른 바퀴 접점이 셋보다 적거나, 볼록 껍질의 폭(변마다 가장 먼 꼭짓점까지 거리의 최솟값)이 `MIN_SUPPORT_WIDTH` 0.01 m보다 좁다(일직선)면 경고 `worldFewWheels`다. [가정: 1 cm보다 좁으면 무게중심 높이 0.1 m에서도 0.5 m/s²(g·w/2h)만 가속해도 받침 밖으로 나가 늘 넘어짐 쪽으로 계산된다]. 시뮬레이터의 하중 분배와 같은 껍질(`convexHull`)이다.

## 17. 3c가 기대는 수치 안정화 상수

LCP 풀이와 한계 근방 상수는 물리 값이 아니라 안정화·반올림 상수다(상세는 `motors-joints.md` §8.6). 3c의 바퀴·벽 행도 같은 LCP에 들어가므로 아래 값에 묶인다.

| 상수                     | 값    | 위치              | 상태·근거                                                                                                                                                         |
| ------------------------ | ----- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BPP_TRIES`              | 3     | `articulation.ts` | [가정: 문헌의 보통 값 3–10(Júdice–Pires의 p̄)]                                                                                                                     |
| `LCP_REGULARIZATION`     | 1e-9  | `articulation.ts` | [가정: 조건수 1e9라 배정밀도 LDLᵀ가 다룸, ODE CFM·MuJoCo 구속 정칙화 R과 같은 방식]. 같은 방향의 행(관절 쿨롱 마찰과 한계 등)이 있으면 A가 특이한 양반정치라 필요 |

| `LIMIT_TOLERANCE`        | 1e-12 | `articulation.ts` | [가정: FTC 관절 값(1e-3–10 m·rad)의 배정밀도 반올림보다 크고 측정할 수 있는 침투(µm)보다 훨씬 작음]                                                               |

`solveBoxLcp`가 이 상수들을 쓰는 방식(`articulation.ts`, 상세는 `motors-joints.md` §8.6): 행마다 대각을 `shift_i = A_ii·LCP_REGULARIZATION`(1e-9)만큼 키운 행렬로 블록 주축 전환을 하고, 대각이 양수가 아닌 행(`!(A_ii > 0)`)이 있으면 'joint dynamics: constraint row has no effect'를 던진다. 허용 오차는 행마다가 아니라 한 문제 전체에서 하나씩이다: 상보성 `tolW = 1e-12·max(1, max_i abs(b_i))`, 경계 `tolL = 1e-12·max(1, max_i abs(lo_i), abs(hi_i))`(유한한 경계만). 행의 처음 상태는 `start`가 주면 그것, 아니면 `lo = 0`이면 아래 경계, `hi = 0`이면 위 경계, 그 밖은 자유다. 주축 전환은 위반한 행(자유 행은 λ가 상자 밖, 경계 행은 w의 부호가 어긋남)을 모두 바꾸는 블록 전환이고, 위반 수가 지금까지 최소보다 줄지 않으면 `BPP_TRIES`(3)번까지만 참은 뒤 가장 큰 첨자 하나만 바꾸며(Murty), 반복이 `LCP_MURTY_ONLY_AFTER`(200)번 이상이면 늘 가장 큰 첨자 하나만 바꾼다. 반복이 `LCP_MAX_ITERATIONS`(2000)를 넘으면 던진다(§12.4). 정칙화가 남긴 차이는 근접점 반복(`LCP_PROXIMAL_STEPS` 8번까지, 원래 A에서 잰 위반이 `tolW` 이하가 되면 멈춤)으로 지우고, 마지막에 λ를 [lo, hi]로 자른다(허용 오차 안의 반올림만 고침). 6a 조밀 LCP 전용 `DENSE_RESTART_ITERATIONS`(32)는 `balls-6a.md`에 있다(3c 바퀴·벽 행만 있는 풀이는 쓰지 않는다).

한계 충격 풀이(`clampLimits`)가 밖에서 준 행(바퀴 견인·롤러 상자, 벽 법선·마찰)도 같은 충격 LCP에 넣는 까닭: 넣지 않으면 부유 기저에서 한계 충격 M̂⁻¹Jᵀλ가 벽 구속을 푼 뒤의 기저를 벽 쪽으로 옮겨(z += h·Δv), 벽에 붙어 민 채 슬라이드를 한계에 박을 때마다 침투가 쌓인다(걸친 꼭짓점의 목표가 0이라 되돌아오지 않음, 3c 리뷰). 본 LCP와 같은 계를 이어 푸는 것이라 행마다 합 λ_본 + λ_충격이 본 LCP의 상자 [lo, hi] 안이고 목표도 같다(충격 λ ∈ [lo − λ_본, hi − λ_본]). 벽 법선은 합 λ ≥ 0이다. 시험 T6d: 슬라이드 12번 박기에서 침투 < 1e-6 m(기어 3.7:1·3 kg, 13.7:1·1 kg, 5.2:1·1.5 kg).

Unity 대응·임시 편차:

- 바퀴 컴포넌트는 Unity WheelCollider처럼 시뮬레이터 전용 설정이다. 바퀴 카드의 마찰 칸은 WheelCollider Friction 자리이고 도움말에 겉보기 μ와 메카넘 환산이 있다.

- Unity WheelCollider의 슬립 곡선(forward/sideways friction curve)은 쓰지 않는다(정확한 쿨롱 + 상자 LCP).
- 필드 벽·구조물과의 접촉에서 로봇이 넘어지지 않는다(알림만). Unity에는 대응이 없는 시뮬레이터 한계다.

| 바퀴 회전 관성 계수           | 바퀴를 축에 걸고 실을 감아 추를 떨어뜨린다. J = m_추·r_축²·(g ÷ a − 1)                                                                                                    |
| 베어링 마찰                   | 바퀴를 손으로 돌린 뒤 감속을 영상으로 잰다. τ = J × 각감속                                                                                                                |
| 하중 필터 τ                   | 재기 어렵다(바퀴 하중을 재는 힘 판이 필요). 수치 안정이 주 목적                                                                                                           |
