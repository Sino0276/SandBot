# HIVE 넘어감·FLOWER 케이지·CELL 트레이(6b) 기준 문서

이 문서는 SandBot 시뮬레이터의 6b 단계(BIOBUZZ HIVE가 한 축으로 도는 동역학 몸체가 되어 CELL에 든 공의 무게로 넘어가고, CELL이 공을 담는 트레이가 되며, FLOWER가 안에 공을 쌓고 아래 회수 구멍으로 꺼낼 수 있는 케이지가 되는 계산, 시작 배치 묶음 `flower`·`hiveCell`, 웹캠 태그가 HIVE 각을 따르는 것, 씬 뷰의 HIVE 움직임·잔상·Field 인스펙터 줄)가 쓰는 치수·상수·수식·알고리즘·결정사항을 한곳에 적는다. 6b의 명세와 계획(`docs/research/6b/spec-6b.md`, `docs/research/6b/plan-6b.md`)과 조사 메모(`cad-geometry-notes.txt`, `web-sources-notes.txt`)·CAD 측정 스크립트(`cad-scripts/`)는 저장소에 있다. 그 밑의 원자료인 FIRST 공식 필드 CAD(STEP)는 FIRST가 배포하는 파일이라 저장소에 넣지 않았고(주소와 sha256은 2.1절), 스크립트가 읽어 낸 중간 결과(메시 JSON·npz)와 PDF에서 뽑은 글·그림도 남지 않았다. 그래서 코드(`src/shared/sim/seasons/biobuzz.ts`·`fieldSpec.ts`·`partShapes.ts`, `src/shared/sim/elements/elementWorld.ts`·`elementData.ts`·`gameState.ts`, `src/shared/sim/collision3d.ts`, `src/shared/sim/vision.ts`)와 CLAUDE.md, `docs/assumptions.md`의 "6b" 표가 곧 원본이다. 각 값은 값 · 단위 · 위치(파일·상수·함수 이름, 줄 번호 없음) · 상태(`[확인: …]`, `[가정: …]`, `[결정: …]`, 표시 없는 코드 값)와 근거를 적었다. 수식은 코드의 변수 이름을 그대로 써서 다시 구현할 수 있게 했다. 단위는 내부 SI(미터·라디안·킬로그램·초)다. 공 접촉(부드러운 법선·심·마찰·섬·조밀 LCP)은 `docs/reference/balls-6a.md`가, 3D 충돌(SAT·GJK·볼록 껍질·정적 형상)은 `docs/reference/collision.md`가, 필드 데이터(벽·구조물·태그)는 `docs/reference/field-biobuzz.md`가, 카메라 판정은 `docs/reference/sensors-vision.md`가 맡는다. 여기서는 6b가 더하거나 바꾼 것만 적는다.

| `[가정: …]` | 출처 없이 정한 값. 실측으로 바꿀 대상                                  |
| `[결정: …]` | 설계로 정한 값(이유가 주석에 있음). `사용자 결정`은 사용자와 합의한 값 |

### 0.4 데이터 흐름

1. 시즌 데이터(`biobuzz.ts`)가 FLOWER 4개와 CELL 4개에 부품 목록(`parts`)을, 두 HIVE에 동역학 값과 축 조립체 부품을, 레이아웃에 `flower`·`hiveCell` 시작 배치를 싣는다. 모두 코드 상수이고 `resolveSeason`이 깊게 얼린 값을 준다. 프로젝트 파일은 바뀌지 않았다(`PROJECT_VERSION` 14 그대로).
2. INIT 때 렌더러가 세계 설명 v8의 `elements.groups`에 `garden`·`flower`·`hiveCell`을 모두 싣는다(`RUN_ELEMENT_GROUPS`). `field.hiveTipped`는 개인 실행 설정 `hiveState`(HIVE **시작 상태**)다. 공의 번호·위치는 시뮬레이터가 `elementSpawns(field, elements, start, bodyFrame, hiveTipped)`로 푼다.
3. `PhysicsWorld`는 세계 설명에 `elements`가 있고 시즌에 경기 요소가 있을 때만 `ElementWorld`를 만든다. 그때만 HIVE가 움직인다. `elements`가 없으면(개인 실행 설정 `gameElements`를 끈 실행) HIVE는 `field.hiveTipped` 자세로 고정이고 카메라 태그도 시작 자세 그대로다(4ab·4d와 같은 바이트).
4. 하위 단계(1 ms)마다 `ElementWorld.prepare`가 공 접촉에 더해 깨어 있는 HIVE의 멈춤·축 마찰 행과 공–HIVE 부품 접촉 행을 만든다. 로봇에 닿은 공이 HIVE에 닿으면 HIVE도 로봇 섬에 같이 들어가 한 상자 LCP로 풀린다. 나머지 섬은 `finish`에서 따로 푼다(HIVE가 든 섬은 조밀 풀이 한도가 256행이다).
5. 틱 경계에서 `PhysicsWorld.inputs()`가 웹캠 프레임을 만들 때 `hiveAngles()`로 지금 HIVE 각을 넘겨 시작 각과 다른 HIVE의 태그만 다시 푼다.
6. 메인 `session.ts`가 `gameState` 이벤트에 HIVE 각 `hives`와 넘어간 횟수 `hiveTips`를 공 자세와 같은 틱·같은 16 ms 박자로 싣고, 끝에 `finalHives`를 싣는다. HIVE가 넘어가는 순간 `hiveTip` 알림(HIVE마다 실행에 한 번)이 Console 안내가 된다.
7. 렌더러가 HIVE carrier 그룹 안쪽 움직임 그룹을 시뮬레이터 각으로 명령형으로 돌리고(React 다시 그리기 없음), 끝나면 시작 상태로 돌아가며 끝난 각이 다르면 반투명 잔상을 남긴다. Field 인스펙터가 실행 중 지금 각·넘어간 횟수를, STOP 뒤 다음 INIT까지는 끝난 각·횟수를 보인다.

## 1. 범위와 설계 결정

### 1.1 6단계의 분할과 6b의 범위

6단계(공)는 6a 공 물리 → **6b HIVE 넘어감·FLOWER 케이지·CELL 트레이** → 6c 센서·웹캠이 공을 봄 → 6d 점수·규칙 알림·사람 선수 NECTAR·AUTO→TELEOP 이어 가기로 나뉜다(사용자 결정 11/13).

| 6b에 있는 것                                                                                                              | 6b에 없는 것(뒤 단계·결정)                                                                    |
| ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| HIVE 한 축 동역학(중력 토크·두 멈춤·축 마찰), 넘어감 감지·횟수·알림, 공–HIVE 접촉                                         | 점수·규칙 알림(G417 위로 향한 CELL에만 LAUNCH 등)·HIVE 넘어감 시각 기록(6d)                   |
| CELL 트레이(밑판·옆벽·지붕·Back Skin·리브·Base Tube·받침, 입구 열림)가 공을 담고 넘어간 뒤 쏟아 냄                        | 사람 선수 NECTAR(넘어갈 때마다 하나)·AUTO→TELEOP 이어 가기(6d)                                |
| FLOWER 케이지(고리 셋·NECTAR 턱·관 넷·압출재·브래킷·백스톱): 공은 안에 쌓이고 로봇 인테이크가 아래 회수 구멍으로 꺼냄     | FLOWER 득점 부피(위 고리–가운데 고리 사이)·CELL에 남은 공 세기(6d)                            |
| 시작 배치 `flower`(FLOWER마다 POLLEN 4개)·`hiveCell`(위로 향한 CELL마다 NECTAR 3개), 세계 설명 v8                         | 센서·웹캠이 공·HIVE·CELL·케이지를 봄(6c: 4c 광선·4d 가림은 여전히 봉투 상자와 표시 전용 CELL) |
| 웹캠 태그가 HIVE 각을 프레임마다 따름, 씬 뷰 HIVE 움직임·잔상, Field 인스펙터 HIVE 줄, 기준 해시 여덟째 다시 잼·열째 새로 | 로봇이 HIVE에 닿는 것(로봇 몸체는 HIVE에 닿지 않음: 사용자 결정), 댐퍼 행정·힘 모델           |

### 1.3 설계 결정(명세 `spec-6b.md` §0)

| 결정                                       | 내용                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HIVE = 축에 묶인 의사 몸체                 | HIVE는 `ElementWorld`의 공 뒤 마디(`count + k`)다. 6칸 속도 자리를 쓰되 역질량 0·역관성 1/I이고 행의 HIVE 부분은 늘 `a = [0, 0, 0, 0, s, 0]`이다. 그래서 `articulation.ts`·`islands.ts`·`denseLcp.ts`는 바꾸지 않았고 공만 있는 풀이는 비트 그대로다. ### 1.4 Unity 대응과 임시 편차

6b는 편집기 UI가 아니라 시즌 데이터와 시뮬레이터 내부(와 Field 인스펙터의 읽기 전용 줄)라 코드·명세·CLAUDE.md는 Unity 대응을 적지 않았다(출처 기록 없음). ### 3.5 대칭 생성

`mirrorPartShape`·`mirrorPart`(`symmetry.ts`): 중심은 부호 반전(`mirrorVec3`, −0 없음), 회전은 Rz(π)를 앞에 곱함(`mirrorRotation`), 크기·다각형·반지름은 그대로(자기 틀 값이라). 쓰임·이름·순서는 그대로라 짝 부품은 같은 순번이다. `mirrorStructure`·`mirrorHive`는 부품 목록을 그대로 거울로 만든다. ## 9. HIVE 동역학(`ElementWorld`)

`src/shared/sim/elements/elementWorld.ts`. 6a의 하위 단계 구조(`prepare` → `Articulation.step` → `finish`)는 그대로이고 HIVE가 공 뒤의 마디로 끼어든다. HIVE가 없는 시즌·세계(공만 있는 풀이)와 건드리지 않은 HIVE는 6a와 바이트 그대로다.

### 9.1 상태(HIVE k마다, `FieldSpec.hives` 순서)

### 9.4 자유 예측(`predictHive`)

ω* = ω + h·massMoment·g·sin θ / I, 칸 4에만 쓴다(`Math.sin` θ: 새 초월 함수 사용이라 기준 해시 열째에만 걸린다). 공의 `predict`처럼 중력 외에 항력·Magnus는 없다.

### 9.5 멈춤·축 마찰 행(접촉 없음, `BallRow.contact = −1`)

`hiveRows(k, h)`. `dynamics`가 없으면 행이 없다. 행 키는 `ghl.h<k>`·`ghu.h<k>`·`ghf.h<k>`(`g`로 시작해 기존 키 접두어와 안 겹친다). 접촉이 없는 행이라 `contacts[row.contact]`를 읽는 곳(`rowCount`·`softenOneWay`·`solveSingleContact`·끼임 계산)은 `contact < 0`을 거른다.

| 행                   | HIVE 부분 `a`    | 목표(`target`)        | 상자(`lo`, `hi`)                   | 순응 | 뜻                                                                                         |
| -------------------- | ---------------- | --------------------- | ---------------------------------- | ---- | ------------------------------------------------------------------------------------------ |
| 아래 멈춤 `ghl.h<k>` | `[0,0,0,0,+1,0]` | `min(lower − θ, 0)/h` | 0, ∞                               | 0    | ω⁺ ≥ target: θ + h·ω⁺ ≥ lower(이미 멈춤 위면 지나간 각을 밀어내지 않는다)                  |
| 위 멈춤 `ghu.h<k>`   | `[0,0,0,0,−1,0]` | `min(θ − upper, 0)/h` | 0, ∞                               | 0    | −ω⁺ ≥ target: θ + h·ω⁺ ≤ upper                                                             |
| 축 마찰 `ghf.h<k>`   | `[0,0,0,0,+1,0]` | 0                     | −pivotFriction·h, +pivotFriction·h | 0    | 쿨롱 마찰: ω⁺ = 0을 향한 충격의 크기가 상자를 넘지 못한다(고정 상자, `friction` 필드 없음) |

멈춤은 한쪽 행이고 반발·순응·위치 보정이 없다("단단한 댐퍼, 되튐 없음" `[가정]`).

### 9.6 적분과 넘어감(`integrateHive`)

`θ ← θ + h·ω⁺`. θ ≤ `lower`이면 θ를 `lower` 상수 그대로로 두고 정지 −1, θ ≥ `upper`이면 `upper` 상수로 두고 정지 +1. θ가 바뀌었으면 표시 `moved`를 켠다. ω는 풀린 값 그대로 쓴다. 멈춤에 닿은 채 중력이나 공이 멈춤 쪽으로 밀면 멈춤 행이 그 방향 ω를 정확히 0으로 지우고 각은 상수 그대로다(시험: 넘어간 뒤 5 s 동안 각이 상수 그대로이고 ω ≥ 0).

**넘어감**(CM 10.5.1: 다른 안정 자세로 가서 반대 댐퍼가 닿기 시작함): 정지가 0이 아니고 `restStop`과 다르면 `restStop ← 정지`, `tips[k]++`, `moved ← true`, 알림 `hiveTip { hive: 'red' | 'blue' }`. 시작의 `restStop`은 시작 정지(θ가 상수와 같은 쪽)다. `restStop`이 0이면(`initialHives`가 멈춤 사이에서 시작) 처음 닿은 멈춤을 넘어감으로 센다. 알림은 같은 params가 실행마다 한 번이라 HIVE마다 Console 한 줄이고 횟수는 `tips`·`gameState.hiveTips`가 센다. 같은 HIVE가 되돌아 넘어가면 `tips`가 2가 된다.

| 섬 풀이 한도 | HIVE가 든 섬(마디가 오름차순이라 마지막 마디가 HIVE)은 조밀 LCP 한도 `HIVE_ISLAND_DENSE_ROWS` 256행, 그 밖은 `ISLAND_DENSE_ROWS` 60. 넘으면 PGS 30회와 `elementIslandLarge`. `[결정: 넘어감 기준이 PGS 근사로 흔들리지 않게]`                                                                              |
| 빠른 길      | `solveSingleContact`(공 하나·접촉 하나)는 `e ≥ n`(HIVE만 있는 섬)이면 쓰지 않는다                                                                                                                                                                                                                          |
| 끼임·붙들림  | HIVE 접촉은 `f < 0`이라 로봇·정적 접촉처럼 "단단한 쪽"으로 센다(`pinchedContacts`)                                                                                                                                                                                                                         |

### 9.8 깨움과 잠들기(`sleepStep`)

| 항목               | 값·식                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 느린 시간          | 깨어 있는 HIVE마다 `\|ω\|·HIVE_ARM < SLEEP_SPEED`(`HIVE_ARM` 0.545 m `[결정: CELL 입구 x_b 0.544982까지의 팔]`, `SLEEP_SPEED` 5e-3 m/s)이고 **구동되는 중이 아닐 때** `hiveTimer += h`, 아니면 0                                                                                                                                                                                          |
| 구동 판정 `driven` | `!atStop && friction > 0 && \|impulses['ghf.h<k>']\| ≥ friction·(1 − 1e-9)`. `atStop` = θ가 `lower`·`upper` 상수와 `===`, `friction` = pivotFriction·h. 멈춤 사이에서 축 마찰 행이 상자 끝(미끄러지는 중)이면 알짜 토크가 마찰을 넘어 기어 나가는 중이라 ω가 문턱 아래여도 쉬는 것이 아니다. 정적 마찰로 버티는 HIVE(행이 상자 안)와 멈춤에서 쉬는 HIVE는 그대로 느리다 `[결정: 6b 리뷰]` |
| 묶음이 함께 잔다   | 공끼리 접촉과 깨어 있는 HIVE–공 접촉으로 이은 묶음(`UnionFind`) 전체가 `SLEEP_TIME`(0.5 s) 넘게 느려야 함께 잠든다(로봇에 닿은 공이 있으면 안 잠든다). 잠들면 HIVE의 ω는 `+0`이고 θ는 지금 값 그대로다(멈춤에 닿아 쉬면 그 멈춤 상수)                                                                                                                                                     |
| 깨움               | 깨어 있는 공이 잠든 HIVE 부품에 닿으면 HIVE가 깬다(`wakeHive`: `hiveAsleep` 0, `hiveTimer` 0). 깬 HIVE가 닿은 잠든 공도 깬다                                                                                                                                                                                                                                                              |
| `maxSpeed`         | HIVE 속도는 `maxSpeed`(공 넓은 단계 띠)에 들어가지 않는다                                                                                                                                                                                                                                                                                                                                 |
| 구동 판정의 이유   | 구동 판정이 없으면 알짜 토크가 임계를 1.4 %까지 넘는 짐(4N+1P 놓기)이 −29.87°에서 잠들어(공도 함께) 넘어감을 놓쳤고, 보정 임계가 잠들기를 켠 쪽이 1.3–1.9 % 낮았다                                                                                                                                                                                                                        |

## 10. 공–HIVE 접촉

### 10.1 넓은 단계와 좁은 단계(`hiveTouches`)

공마다·HIVE마다 하위 단계마다 부르는 곳이라 할당 없이 쓴다(빈 결과는 공유 상수 `NO_HIVE_TOUCH`).

| 단계      | 식·내용                                                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 띠        | band = (\|v_공\| + \|ω\|·reach)·h + `COLLISION_MARGIN`(1 mm). 공 중심이 피벗에서 `reach + r + band` 밖이면 접촉 없음                        |
| 몸체 틀   | c_l = R_y(θ)ᵀ·(c − pivot)(`applyT`, 캐시한 행렬). 몸체 틀 전체 상자 → 부품마다 상자(`r + band` 여유)를 거른다                               |
| 좁은 단계 | 껍질 부품은 `sphereHull`, 원기둥 부품은 `sphereCylinder`(6a와 같은 함수). 결과 법선·점을 R_y(θ)로 필드로 돌려 pivot을 더한다                |
| `first`   | true면 첫 접촉에서 멈춘다(깨우기 판정). 같은 공에 `hiveTouches`가 두 번 불린다(깨움·짝 만들기): 값은 싸지만 한 번만 부르도록 캐시할 수 있다 |

### 10.2 접촉 값(`hivePairs`, 정적 짝 뒤·공끼리 짝 앞)

| 필드        | 값                                                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 짝 구분     | `f = −1`, `body = −2`, `hive = k`, `dynamic = false`                                                                            |
| 토큰·행 키  | `e<i>/h<k>p<j>`, 행 `gn.`·`gt1.`·`gt2.` + 토큰. 키 번호는 `staticLeafCount + robotShapeCount + n + hivePartOffset[k] + j`       |
| 마찰 μ      | (공 μ + 부품 μ)/2, 부품 μ = CELL 구조물 `friction`(0.4) 또는 `HIVE_PART_FRICTION`(0.4). 공 μ는 종류별(POLLEN·NECTAR 0.5) → 0.45 |
| 반발        | `restitution.hard`(0.64) `[가정: PETG 껍질 = 딱딱한 면]`                                                                        |
| 스프링      | `CONTACT_STIFFNESS_PER_PLATE`(2) × `plateStiffness`(POLLEN 3000, NECTAR 4500 N/m), 질량 = 공 질량, 심 = `coreDepthRatio`(0.3)·r |
| 다른 몸체 ω | `[0, ω_k, 0]`(굴림·회전 저항의 상대 각속도). HIVE는 그 반작용을 받지 않는다(로봇과 같은 근사)                                   |

### 10.3 행의 HIVE 부분

HIVE 부품에 닿은 깨어 있는 공의 접촉 행(법선·접선 둘)에는 공 부분(6a와 같다)과 HIVE 부분이 든다. 행 속도는 (공 접촉점 속도 − HIVE 접촉점 속도)의 방향 d 성분이고 HIVE 접촉점 속도는 ω ŷ × (p − pivot) = ω·(r_z, 0, −r_x)(r = p − pivot)이다.

| 항목             | 식                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------- |
| HIVE 부분 계수 s | s = −((p − pivot) × d)_y = −(r_z·d_x − r_x·d_z). 법선과 접선 둘 모두. `hivePart(k, s)`                               |
| 마찰 접선 선택   | 상대 미끄럼(공 점 속도 − HIVE 점 속도)이 > 1 mm/s이면 그 방향, 아니면 지난 t1(`frictionTangent`, 5 충돌과 같은 함수) |
| 잠든 HIVE        | 정적 짝(HIVE 부분 없음, 속도 0)                                                                                      |
| 끼임·붙들림      | HIVE 접촉은 단단한 쪽으로 센다(9.7절)                                                                                |

## 11. 보정: 넘어감 기준

### 11.1 공식 보정표(EFG §12.3, FAC 2.3–2.6, Mitigation App. A)

위로 향한 CELL의 Back Skin에 붙여(그리고 밑판에 닿게) 짐을 놓는다. 시험 전 반대 댐퍼는 끝까지 눌려 있다. "필수(Necessary)"는 던져 넣어도, "권장(Preferred)"은 살며시 놓아도다.

| 짐(최종) | 마지막 공을 | 요구                                |
| -------- | ----------- | ----------------------------------- |
| 3N + 1P  | —           | (표에 직접 없음, 3N + 2P의 앞 단계) |
| 3N + 2P  | 던짐        | 넘어가지 않음(필수)                 |
| 3N + 3P  | 놓음 / 던짐 | 넘어감(권장 / 필수)                 |
| 6P       | —           | (7P의 앞 단계)                      |
| 7P       | 던짐        | 넘어가지 않음(필수)                 |
| 8P       | 놓음 / 던짐 | 넘어감(권장 / 필수)                 |

시험은 모든 줄을 놓기·던지기 둘 다로 돌린다: 3N+1P·3N+2P·6P·7P는 넘어가지 않고, 3N+3P·8P는 한 번 넘어간다(`hive.test.ts`).

### 11.2 해석 창(명세 부록 B)

공을 Back Skin과 밑판에 닿게 놓은 한 줄(7 POLLEN은 7 × 0.0711 = 0.4977 ≤ 안쪽 너비 0.512014 m, 8번째는 둘째 줄 x_b + √3·r에 첫 줄 두 공 사이 가운데)로 θ = −30°에서 받침 토크 팔 x′ = x_b cos θ + z_b sin θ를 잰 토크/g:

| 짐      | 토크/g(kg·m) | 요구      |
| ------- | ------------ | --------- |
| 3N + 1P | 0.036063     | —         |
| 3N + 2P | 0.042020     | 안 넘어감 |
| 3N + 3P | 0.047978     | 넘어감    |
| 6P      | 0.035746     | —         |
| 7P      | 0.041704     | 안 넘어감 |
| 8P      | 0.048989     | 넘어감    |

창 [0.042020, 0.047978], 가운데 0.044999. 멈춤에서 받치는 토크 = massMoment·g·sin 30°이므로 massMoment = 0.044999/0.5 = 0.0900(계산값 0.089998). 창 반폭 0.00298 kg·m라 축 마찰은 0.0292 N·m 아래여야 한다(코드 0.005).

### 11.3 시뮬레이터가 잰 임계(`hive.test.ts`, 이분법, 허용 2e-5)

시뮬레이터가 공을 접촉 모델로 직접 놓아(해석 위치가 아니라) 이분법으로 잰 값이다. massMoment가 이 값 **미만**이면 넘어간다(잠들기를 켠 쪽과 끈 쪽이 같다: 6b 리뷰 뒤).

| 짐      | 놓기    | 던지기  | 요구      |
| ------- | ------- | ------- | --------- |
| 3N + 1P | 0.07116 | 0.07528 | 안 넘어감 |
| 3N + 2P | 0.08310 | 0.08669 | 안 넘어감 |
| 3N + 3P | 0.09503 | 0.09860 | 넘어감    |
| 6P      | 0.07054 | 0.07380 | 안 넘어감 |
| 7P      | 0.08247 | 0.08560 | 안 넘어감 |
| 8P      | 0.09706 | 0.10122 | 넘어감    |

이 문서를 쓰며 12개를 모두 이분법(massMoment 0.05–0.13을 13번 나눔, 한 번에 8 s 실행)으로 다시 쟀고 같은 값이다(최대 차 2e-5). 안 넘어가야 하는 줄(3N+1P·3N+2P·6P·7P)은 massMoment가 놓기·던지기 임계 가운데 큰 값보다 **커야** 하고(가장 큰 것은 3N+2P 던지기 0.08669), 넘어가야 하는 줄(3N+3P·8P)은 작은 값보다 **작아야** 한다(가장 작은 것은 3N+3P 놓기 0.09503).

### 11.6 넘어감에 걸리는 시간(계산값)

1 ms 틱, θ가 멈춤에서 0.01 rad(0.57°) 벗어난 틱부터 반대 멈춤에 닿을 때까지다.

| 짐      | 놓기   | 던지기 |
| ------- | ------ | ------ |
| 3N + 3P | 2.27 s | 2.22 s |
| 8P      | 2.15 s | 2.08 s |

멈춤을 처음 떠난(θ ≠ 멈춤 상수) 틱은 놓기 3 ms, 던지기 93–117 ms이고 0.57° 벗어난 틱은 놓기 0.47–0.55 s, 던지기 0.34–0.38 s다. 임계를 조금 넘는 짐이라 느리게 시작하고 한계 가까운 짐은 약 2 s를 기어간다. 더 무거운 짐은 더 빨리 넘어간다. 넘어감 시간은 가정한 관성(0.386 kg·m²)·축 마찰에 따라 달라진다(`hive.test.ts`는 0.2–3 s로만 확인한다).

## 12. 카메라가 HIVE 각을 따른다

4d 웹캠의 태그 자세는 HIVE carrier 위 태그(30–45, `field-biobuzz.md` §8)라 HIVE가 움직이면 태그 꼭짓점이 바뀐다.

| 항목                                | 내용                                                                                                                                                                                                                                                                   |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tagFieldPoseAt(field, tag, angle)` | 지금 `tagFieldPose`의 문장 그대로(`rotationMatrix({x: 0, y: angle, z: 0})` → `applyMatrix3` → pivot 더하기 → `matMul3`). `tagFieldPose`는 시작·넘어간 각으로 이것을 부른다. 같은 각이면 비트로 같다. carrier `field`는 각을 보지 않는다                                |
| `FieldVision`                       | 생성자가 `sources`(id 오름차순 태그), `tags`(시작 상태로 푼 판정 자료), `startAngles`([빨강, 파랑], 그 carrier의 태그가 없으면 NaN)를 만든다                                                                                                                           |
| `observe(…, hive)`                  | `hive`(null 또는 [빨강, 파랑] 각)가 없거나 각이 생성자의 각과 `===`이면 생성자에서 푼 자료를 계산 없이 쓴다. 아니면 각이 바뀐 carrier의 태그만 `tagFieldPoseAt`으로 다시 풀고 나머지는 그대로 쓴다. 마지막 각과 `===`이면 그 결과를 다시 쓴다(`tagsAt`의 `moved` 캐시) |
| `FieldCameras.read(…, hiveAngles)`  | 판정하는 프레임(프레임 틱의 스트리밍 중인 AprilTag 웹캠)에서만 `hiveAngles?.()`를 부른다. `PhysicsWorld.inputs()`는 `() => elements ? elements.hiveAngles() : null`을 넘긴다. 경기 요소가 없는 세계는 부르지 않는다(시작 자세 태그, 4d와 바이트 그대로)                |
| 결과                                | 잠든 HIVE의 각은 시작 각 상수와 `===`라 태그 꼭짓점이 정적 길과 `Object.is`로 같다. 넘어가면 태그가 HIVE 각을 따른다(가운데 각은 둘 사이)                                                                                                                              |
| 사이드카                            | 바뀌지 않았다. 팀 코드의 필드 자세 상수(예: 묶음 `AprilTagClusterMetadata`)는 정적이라 HIVE가 넘어간 뒤 `robotPose`는 실제 필드처럼 어긋난다(태그가 움직였는데 라이브러리의 묶음 자세는 그대로)                                                                        |
| 판정(가림 등)                       | 4d와 그대로다: 4d 가림은 `occludes` 구조물(HIVE CELL·몸체는 아님)만 본다. HIVE가 넘어가도 HIVE 몸체·CELL·케이지 부품은 광선·가림에 들지 않는다(6c)                                                                                                                     |

사용자 결정(11/19): FLOWER 상세 형상을 공과 로봇 3D 충돌에 쓴다. 8째 장면은 마지막 단계(2.7–3.2 s, 옆걸음 `mecanum(0, −0.5, 0)`)에서 섀시 왼쪽이 FLOWER `<3>`(구조물 11)에 막힌다. 6b 전에는 봉투 상자 한 면이 법선·행(`cn.rk0/s11.…`)을 정했는데, 지금은 케이지의 아래·가운데·위 고리 판·관·압출재·브래킷·백스톱(로봇 부품 15개, 토큰 `s11p<j>`)이 닿는 면·점·행을 정한다. 그래서 그 마지막 구간의 접촉이 바뀌어 해시가 달라졌다. 시험의 바뀐 점:

- `cn.rk0/s11` 단언이 접두어 `cn.rk0/s11p` 확인으로 바뀌었다(`collisionPerf.test.ts`도 정규식 `^cn\.rk0\/s11p\d+$`).
- 케이지 옆을 미끄러져도 하위 단계 충돌 행이 `MAX_COLLISION_ROWS` 28 안이고(`mostRows` > 0, ≤ 28) `collisionLimit` 알림이 없음을 확인한다(한도를 올리지 않았다).
- 이유는 시험 주석과 CLAUDE.md에 적혀 있다.

### 14.4 기준 해시 기록의 바뀜 방향
