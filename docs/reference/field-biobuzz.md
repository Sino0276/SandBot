# 시즌 필드 BIOBUZZ 기준 문서 (4ab·4e)

이 문서는 2026-27 FTC 시즌 필드(BIOBUZZ)를 SandBot이 어떻게 표현하는지, 그 숫자 하나하나와 알고리즘을 한곳에 모은 기준 문서다. 범위는 `src/shared/sim/seasons/`(시즌 데이터·대칭·시작 프리셋·AprilTag 자세·tag36h11 그림·평면 기하·데이터 검사), `src/shared/sim/field.ts`('none' 시즌 상수), `src/shared/sim/fieldContact.ts`(평면 경로의 구조물 접촉), `src/renderer/src/field/`(필드 CAD 보기 4e의 불러오기·합치기·저장소·알림), 그리고 이 데이터를 그리는 씬 뷰 모델(`fieldViewModel.ts` 등)과 필드 CAD 정렬 규칙이다. 값의 원천은 코드이고(상수·주석), 의도는 CLAUDE.md와 `docs/assumptions.md`에서 가져왔다. 코드에 출처가 적혀 있지 않은 값은 "출처 기록 없음"으로 적었고, 출처·숫자를 지어내지 않았다. 센서(4c)·웹캠(4d)·충돌(5)·공 물리(6a)가 이 데이터를 어떻게 쓰는지는 각 단계 문서의 몫이고, 여기서는 연결 표(§14)만 둔다.

## 0. 읽는 법

### 0.1 상태 표기

코드 주석의 표기를 그대로 쓴다.

| 표기      | 뜻                                                                                                                                                                                 |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [확인: …] | 공식 CAD·Field Assembly Checklist(FAC; `biobuzz.ts` 머리 주석은 "FAC(필드 검수 치수)")·게임 매뉴얼(CM; CLAUDE.md는 Competition Manual)·SDK 소스 등에서 잰 값. 주석이 출처를 적는다 |
| [가정: …] | 출처 없이 정한 값. 실측으로 바꿀 대상                                                                                                                                              |
| [결정: …] | 설계로 정한 값(재는 값이 아님). 사용자 결정은 "사용자 결정"으로 따로 적는다                                                                                                        |
| 코드 값   | 주석에 태그가 없는 값. 주석의 설명만 옮겼다                                                                                                                                        |
| 환산      | 이 문서가 단위만 바꾼 값(코드에 그 글자는 없다). 1 in = 0.0254 m                                                                                                                   |

주석이 가리키는 `spec-4ab §…`, `synthesis §…`, `FAC 3.5`, `CM 9.3` 같은 문서 번호는 원본이 사라져(§20) 이 저장소에서 따라갈 수 없다. 그 번호는 "주석 인용"으로만 적었다.

### 0.2 단위·표기 규약

- 코드의 길이는 미터, 각은 라디안이다. 표의 `in`은 환산이다.
- 필드 좌표는 §1.1의 FTC 필드 좌표다. 회전은 X(롤)·Y(피치)·Z(요) 라디안이고 적용 순서는 Three.js Euler `'ZYX'`, 곧 R = Rz·Ry·Rx다.
- 위치 열은 파일 경로와 상수·함수 이름이다(줄 번호 없음). `biobuzz.ts`는 `src/shared/sim/seasons/biobuzz.ts`, `fieldSpec.ts` 등도 같은 폴더다.
- 배열 순서가 계산 순서다(구조물 행 키 `s<순번>`, 태그 순서 등).

### 1.2 Rz(π) 대칭 생성

`symmetry.ts`. 시즌 데이터는 짝마다 한쪽(빨강, 또는 구조물은 앞 순번)만 적고 다른 쪽은 이 함수들로 만든다. [가정: 파랑 = 빨강의 180° 회전] CAD 비대칭(≤ 0.016 in)은 버리고 공칭 대칭값을 쓴다.

핵심 규칙은 cos·sin 행렬로 돌리지 않고 정확한 부호 반전(`neg`)과 각 감기(`wrapPi`)만 쓰는 것이다. 그래서 생성값은 원본과 비트까지 대칭이고 −0을 만들지 않는다(`checkFieldSpec`이 −0을 오류로 본다).

| 함수                               | 식                                                                                                                                                                              | 비고                                               |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `neg(v)`                           | v = 0이면 0, 아니면 −v                                                                                                                                                          | −0 방지                                            |
| `wrapPi(a)`                        | a > π면 a − 2π, a ≤ −π면 a + 2π (한 번만, 입력은 (−3π, 3π])                                                                                                                     | 결과 (−π, π]                                       |
| `ROTATE_PI`                        | 행 우선 [−1,0,0, 0,−1,0, 0,0,1]                                                                                                                                                 | 데이터 시험이 회전 행렬을 비교할 때                |
| `mirrorVec3(v)`                    | (neg(x), neg(y), z)                                                                                                                                                             |                                                    |
| `mirrorRotation(r)`                | (r.x, r.y, wrapPi(r.z + π))                                                                                                                                                     | Rz(π)·Rz(c)Ry(b)Rx(a) = Rz(c + π)Ry(b)Rx(a)라 정확 |
| `mirrorCarrier`                    | hiveRed ↔ hiveBlue, field는 field                                                                                                                                               |                                                    |
| `mirrorAlliance`                   | red ↔ blue                                                                                                                                                                      |                                                    |
| `mirrorStructure(s)`               | shape.center → mirrorVec3, shape.rotation → mirrorRotation, size·radius·height 그대로, carrier → mirrorCarrier, 나머지 필드(key·solid·occludes·sensed·material·friction) 그대로 |                                                    |
| `mirrorTag(t)`                     | id + 8, size 그대로, carrier 반대, position → mirrorVec3, rotation → mirrorRotation, cluster → 짝 이름                                                                          | `TAG_ID_MIRROR_OFFSET = 8`                         |
| 묶음 이름 짝(`TAG_CLUSTER_MIRROR`) | RED SCORING → BLUE AUDIENCE, RED AUDIENCE → BLUE SCORING                                                                                                                        | SDK `getBioBuzzTagLibrary` 묶음 이름과 같음        |
| `mirrorRect([x0,y0,x1,y1])`        | [neg(x1), neg(y1), neg(x0), neg(y0)]                                                                                                                                            |                                                    |
| `mirrorTape(t, material)`          | alliance 반대, rect 반전, `offField` 유지, material은 상대 얼라이언스 테이프 재질(빨강 ProGaff → electric blue)                                                                 |                                                    |
| `mirrorZone`·`mirrorKeepOut`       | rect 반전, 구역은 alliance 반대                                                                                                                                                 |                                                    |
| `mirrorHive(h)`                    | key 반대, pivot → mirrorVec3, startAngle → neg, tippedAngle → neg                                                                                                               | 각 부호 반전의 근거는 아래                         |
| `mirrorWall`                       | red ↔ blue, audience ↔ scoring                                                                                                                                                  |                                                    |
| `mirrorPreset(p, key)`             | alliance·wall 반대, along → [neg(p.along[1]), neg(p.along[0])], yaw → wrapPi(p.yaw + π), key는 인자(라벨이 위치를 말하므로 빨강과 이름이 다르다)                                |                                                    |
| `mirrorElementKind`                | nectarRed ↔ nectarBlue, pollen 그대로                                                                                                                                           |                                                    |

HIVE carrier 데이터 틀에서의 대칭: 파랑 carrier 데이터 = Rz(π)·빨강 carrier 데이터이고, Rz(π)·T(p)·R_y(θ) = T(Rz(π)p)·R_y(−θ)·Rz(π)다. 그래서 파랑 HIVE의 각은 빨강 각의 부호를 바꾼 값이다(`symmetry.ts` 머리 주석). carrier 위 요소(CELL·태그)의 데이터는 carrier 틀 기준이고, 파랑 carrier 그룹에서도 같은 틀 규칙(필드 자세 = T(pivot)·R_y(θ)·T(position)·R_zyx(rotation))이 적용된다.

### 1.3 로봇 좌표와의 관계

로봇 좌표는 X 앞·Y 왼쪽·Z 위, 원점 로봇 중심 바닥이다(CLAUDE.md). 필드 위 로봇 자세는 (x, y, yaw)이고 외곽 꼭짓점의 필드 좌표는 `placeFootprint`: p = R(yaw)·v + (x, y), R(yaw) = [[cos, −sin],[sin, cos]]다(`fieldGeometry.ts`).

### 9.6 스냅 알고리즘(`snapRobotToStart`)

입력: 외곽 footprint(로봇 좌표 꼭짓점), 프리셋, innerHalf, target(외곽 중심의 벽 방향 목표, 없으면 구간 가운데), facing.

1. yaw = facingYaw(preset, facing). 원점에 둔 외곽을 돌린 꼭짓점 w_k = R(yaw)·v_k(로봇 원점이 외곽 중심이라는 보장은 없다: CAD 경계 상자).
2. (n, u) = presetWallFrame(wall). u_k = u·w_k, uMin·uMax = min·max, width = uMax − uMin, available = a1 − a0.
3. width > available + 1e-9이면 `{ok: false, reason: 'tooWide', width, available}`.
4. center = target ?? (a0 + a1)/2, lo = a0 − uMin, hi = a1 − uMax. s = lo > hi ? (lo + hi)/2 : clamp(center − (uMin + uMax)/2, lo, hi). (lo > hi는 1e-9 허용 안에서 구간보다 넓은 경우다.)
5. d = innerHalf − max_k(n·w_k)(가장 바깥 꼭짓점이 벽 면에 닿음, 간격 0·여유 없음).
6. pose = (d·n + s·u, yaw). 벽 행 목표가 −max(gap, 0)/h라 1 ulp 걸쳐도 밀어내지 않는다(주석).

`presetTarget`: 지금 외곽(자세로 놓은 것)의 모든 꼭짓점이 프리셋 사각형 안(허용 1e-6)이면 그 축 정렬 상자 중심의 벽 방향 좌표, 아니면 undefined [결정: synthesis §2.7 "지금 로봇의 벽 방향 좌표"의 해석]. `matchingPreset`: 프리셋 순서 × `START_FACINGS` 순서(default, reverse, left, right)로 스냅해 위치 1e-6 m·요 1e-9 rad 안이면 그 (key, facing)을 돌려준다. `startConflicts`: `fieldOverlaps`(벽·solid 구조물) 다음 loadingZone(두 얼라이언스, zones 순서)과 1e-6 넘게 겹치는 것(`{kind: 'zone', index}`).

### 9.7 UI 동작(렌더러, 요약)

- 로봇 인스펙터 "시작 위치": 프리셋 선택칸(얼라이언스 묶음)과 벽을 보는 면 선택칸. 지금 면에서 tooWide·충돌인 프리셋과, 맞는 프리셋을 다른 면으로 다시 스냅하면 tooWide·충돌인 면은 비활성. 'none'·모르는 시즌은 흐린 한 줄. 썼을 때 결과가 지금 자세와 같으면 쓰지 않는다(아니면 `setLocalTransform` 한 번 = 실행 취소 한 단계).
- 씬 뷰 시작 표시: 프리셋마다 `presetRect` 반투명 사각형(얼라이언스 색, 불투명도 0.32, 흐림 0.1, 바닥 위 0.6 mm). 누른 점을 품는 첫 프리셋(배열 순서)에 그 점의 벽 방향 좌표로 스냅. 끈 클릭(delta > 2 px)·Alt·핸들 직후·핸들 드래그 중·실행 잠금·Field 선택이면 스냅하지 않는다.
- 18 in 정사각 외곽이면 모든 프리셋·면 조합의 스냅이 겹침·충돌 없음이어야 한다(`startPose.test.ts`).

## 13. 구조물 접촉(`fieldContact.ts`, 평면 경로)

바퀴가 있는 부유 기저(바퀴가 있는 로봇)의 외곽 × [0, H] 프리즘과 시즌의 solid 구조물(carrier `field`, [0, H] 단면을 위에서 본 볼록 껍질 또는 세운 원기둥)의 접촉 행을 만든다. `world.ts` `contacts()`가 벽 행 뒤에 붙인다. 세계 설명에 섀시 충돌 형상(`robot.colliders`)이 있으면 이 행은 쓰이지 않고 섀시는 5단계의 3D 충돌을 쓴다(INIT의 실제 실행은 늘 3D 경로). 행은 벽과 같은 모양이다: 법선 한쪽 행 + 접선 마찰 상자, 반발 0, 위치 자르기 없음, 목표 −max(gap, 0)/h라 시작부터 겹친 로봇을 밀어내지 않는다. 구조물 힘은 바닥 높이에 작용한다고 본다(하중 이동 없음, 벽과 같은 한계).

### 13.2 준비(`fieldCollision(field, height)`)

생성자에서 한 번 만든다(시즌·로봇 높이마다 같다): `innerHalf`(벽 접촉 기준면 반폭), `solids = solidFootprints(field, height)`, `friction[k] = field.structures[solids[k].index].friction`, `normals[k]`(다각형 변 i(점 i → i+1)의 바깥 법선 (dy, −dx)/|e|, 원기둥은 null), `structureCount`. `structureContactState`는 구조물마다 앞 하위 단계의 기준 면 `{side: 'q'|'p', face}`(q = 구조물 껍질 면, p = 로봇 외곽 면, 접촉이 없으면 null)를 기억한다.

### 13.3 행 만들기 `structureRows(collision, footprint, pose, velocity, h, m, state)`

1. placed = placeFootprint(footprint, pose), np = placed의 변 바깥 법선. r_max = max_v |v − (pose.x, pose.y)|. 넓은 단계 여유 margin = (|(vx, vy)| + |ω|·r_max)·h + `WALL_MARGIN`.
2. 로봇 외곽 축 정렬 경계 [minX, maxX]×[minY, maxY]를 margin만큼 넓힌 것과 구조물 경계가 겹치지 않으면 그 구조물의 기준 기억을 null로 두고 건너뛴다.
3. 다각형 구조물은 `polygonContact`, 세운 원기둥은 `circleContact`로 접촉 점(필드 좌표 점, 행 법선(로봇을 구조물에서 밀어내는 쪽, 필드 축), 간격 gap(양수면 떨어짐), 특징 키, `robotNormal`(법선이 로봇에 붙어 도는지))을 얻는다.
4. 점마다: r = point − (pose.x, pose.y). 접근 속도 speed = n·(v + ω × r) = n_x(vx − ω·r_y) + n_y(vy + ω·r_x). gap > |speed|·h + `WALL_MARGIN`이면 건너뛴다.
5. 곡률 보정: t = perpendicular(n) = (−n_y, n_x), nr = n·r, ω = 지금 각속도. `robotNormal`이면 g̈ = ω²·nr + 2ω·(t·v), 아니면 g̈ = −ω²·nr. tighten = (h/2)·max(0, −g̈). 로봇 면이 기준이면(법선이 로봇과 함께 돈다) 고정 점까지의 간격이 g̈만큼 줄어 도는 로봇이 하위 단계마다 ω²·|n·r|·h²/2씩 파고든다(전출력 제자리 회전에서 약 1 µm). 구조물 면이 기준이면 g̈ ≥ 0이라 모서리가 면에서 멀어진다(벽과 같음). 지금 속도로 낸 값이라 각가속이 큰 하위 단계에는 µm 단위가 남을 수 있고, 도는 로봇은 꼭짓점 앞에서 그만큼 일찍 멈춘다. 정지·병진만이면 0이라 걸친 시작을 밀어내지 않는다.
6. 행 두 개(키 접두어 `n`·`t`, 키 본체 `s<구조물 순번>.<특징>`): 법선 행 `{key: 'n'+body, j: [d.x, d.y, −d.x·r_y + d.y·r_x, 0…](길이 m), target: −max(gap, 0)/h + tighten, lo: 0, hi: ∞}`, 접선 행 `{key: 't'+body, j: row(t), target: 0, lo: 0, hi: 0, friction: {normal: 'n'+body, mu}}`(상자 ±μ·λ_n). 순서는 구조물 순번 → 점(사건 변 끝점 순, 기준 면 점 다음 참 축 보충 점) → n행 다음 t행. LCP 주축 선택과 기준 해시가 이 순서에 묶여 있다.

### 13.4 다각형–다각형 `polygonContact`(Box2D `b2CollidePolygons` 꼴)

- 분리: `faceSeparations(a, normals, b)[i] = min_k n_i·(b_k − a_i)`(변 순번 순). sepQs = 구조물 껍질 q의 각 면 → 로봇 p, sepPs = 로봇 면 → 껍질. iMax·jMax = 가장 큰 분리의 면(같으면 작은 번호), sepQ·sepP는 그 값.
- max(sepQ, sepP) > margin이면 접촉 없음(null, 기억도 null).
- 히스테리시스: 앞 기준이 q이고 sepQs[앞 면] ≥ sepQ − `REFERENCE_TOLERANCE`면 iStar = 앞 면(아니면 iMax). 앞 기준이 p이고 sepPs[앞 면] ≥ sepP − `REFERENCE_TOLERANCE`면 jStar = 앞 면(아니면 jMax).
- 기준 면: robotFace = (앞 기준이 p) ? sepP > sepQ − `REFERENCE_TOLERANCE` : sepP > sepQ + `REFERENCE_TOLERANCE`. reference = robotFace ? {p, jStar} : {q, iStar}. 구조물 면을 우선해 모서리 대 모서리에서 법선이 뒤집히지 않게 한다. 행 키에 기준 면을 넣어 법선이 바뀌면 키도 바뀌게 한다(앞 하위 단계의 같은 키 충격·LCP 활성 집합을 다른 법선에 쓰지 않게, Box2D 특징 id와 같은 뜻).
- 자르기 `clipContact`: 기준 다각형 r(면 f: 점 v1 → v2, 법선 n_ref), 사건 다각형 s. 사건 변 e = s의 변 중 법선과 n_ref의 내적이 가장 작은 것(같으면 작은 번호), 끝점은 e·(e+1) mod |s|. τ = (v2 − v1)/|v2 − v1|, lo = τ·v1, hi = τ·v2. 선분을 τ·x ≥ lo, τ·x ≤ hi 두 반평면으로 차례로 자른다(밖에 있던 끝점은 교점으로 바뀌되 그 끝점의 꼭짓점 번호를 그대로 가진다, 둘 다 밖이면 접촉 점 없음). 남은 점마다 gap = n_ref·(c − v1). 로봇 면이 기준이면 점은 구조물 껍질 변 위, 행 법선은 −n_ref, 특징 `p<면>.c<껍질 꼭짓점>`, robotNormal = true. 구조물 면이 기준이면 점은 로봇 변 위, 행 법선은 n_ref(구조물 바깥 법선, 필드 고정), 특징 `q<면>.r<로봇 꼭짓점>`, robotNormal = false.
- 참 분리 축 보충: trueReference = sepP > sepQ ? {p, jMax} : {q, iMax}. trueSeparation = max(sepQ, sepP), referenceSeparation = 고른 기준 면의 분리. trueSeparation > referenceSeparation + `SUPPLEMENT_TOLERANCE`이고 참 축이 고른 기준과 다르면 참 축의 `clipContact` 점도 더한다. 이유(주석): 위치 보정이 없어(목표 −max(gap, 0)/h) 거의 평행한 로봇 변이 짧은 구조물 면 끝을 넘어 걸치면, 구조물 면 기준 점(로봇 변 위를 미끄러지는 점)만으로는 구조물 모서리가 로봇 변으로 미끄러지거나 돌며 들어가는 것을 막지 못하고(L·sin θ ≤ `REFERENCE_TOLERANCE`까지) 되돌리지도 않는다. 보충 행은 기준 행 뒤에 오고 키의 기준 면이 달라 겹치지 않으며 기억은 기준 면 그대로다. 거의 같은 자리·법선의 두 행이 함께 들어가 정칙화한 LCP의 힘 나눔이 반올림에 민감하므로, 대칭 짝의 끝 자세는 1e-9 m 단위로 다를 수 있다(CLAUDE.md).

### 13.5 원기둥–다각형 `circleContact`(Box2D `b2CollidePolygonAndCircle` 꼴, 히스테리시스 없음)

best = max_i n_i·(c − v_i)(가장 가까운 로봇 면 j). best > ρ + margin이면 접촉 없음. best < 0(중심이 외곽 안)이면 변 접촉: 점 c − ρ·n_j, 행 법선 −n_j, gap = best − ρ, 특징 `p<j>.c0`, robotNormal = true. 아니면 변 j의 끝점 v1·v2에서 u1 = (c − v1)·(v2 − v1), u2 = (c − v2)·(v1 − v2). u1 ≤ 0이면 꼭짓점 j, u2 ≤ 0이면 꼭짓점 j+1, 아니면 변 접촉. 꼭짓점 접촉이면 distance = |corner − c|(0이면 변 접촉), distance − ρ > margin이면 없음, 아니면 점 = corner, 행 법선 (corner − c)/distance, gap = distance − ρ, 특징 `q0.r<꼭짓점>`, robotNormal = false.

### 13.6 벽 행 참조(`contact.ts` `wallRows`, 3c)

벽 +x, −x, +y, −y마다 외곽 꼭짓점 k의 간격 gap = innerHalf − s_w·P_k(s_w = ±1, P_k = 꼭짓점 위치의 해당 축 성분)를 재고, gap ≤ |접근 속도|·h + `WALL_MARGIN`인 쌍만 넣는다. 법선 n = −s_w·e_축(안쪽), 접선 t = ẑ × n. 법선 행 목표 −max(gap, 0)/h(한쪽, lo 0, hi ∞), 접선 행은 상자 ±`WALL_FRICTION`·λ_n, `WALL_FRICTION` = 0.4 [가정: 벽은 알루미늄 틀 + 3 mm 폴리카보네이트(AndyMark am-0481), 알루미늄–알루미늄 운동 0.4(Engineering Toolbox), 폴리카보네이트–강철 0.50–0.55의 가운데 쪽(data §7)](`wheelData.ts`). 벽 반폭은 시즌의 `perimeter.innerHalf`다. 벽 힘은 바닥 높이에 작용한다고 본다.

### 16.2 불러오기·상태·알림

- 읽기는 로봇 CAD와 같은 `loadStepModel`(메시 캐시·네이티브/WASM 변환기·진행 알림·[취소])이고 로봇 CAD와 함께 한 번에 하나만 읽는다(`cad/importStore.ts` `canStartImport`). 캐시에 없는 100 MB 넘는 파일(`LARGE_STEP_BYTES = 100 * 1000 * 1000`)은 시작 전에 묻는다.
- 로봇 CAD와 달리 엔티티를 건너뛰었거나 삼각형을 만들지 못한 메시가 있는 결과도 받는다(보기용이라 형상 id가 없어 순번이 밀려도 깨질 것이 없다). 알림(`notifyIncomplete`)을 띄우고 캐시하지 않는다.
- 상태 `projectStore.fieldVisualStatus = { path, status }`(loading·failed·cancelled·missing). 인스펙터 배지 순서(`fieldVisualState`): none → 내 경로 loading → 내 경로 missing → 그려져 있음(shown, 실패·취소보다 먼저: [다시 불러오기]가 실패해도 이전 형상은 그 경로의 유효한 형상) → 내 경로 failed·cancelled → unloaded.
- 열기 순서: 씬을 바꾼 직후 형상 칸과 못 찾은 파일 값을 비우고, 로봇 CAD 위치 다음에 필드 CAD를 상대 → 절대 경로로 찾는다(찾으면 `setFieldVisualFile`로 고친 경로를 연 상태로, 못 찾으면 missing과 `fieldCadMissing` 알림). 읽기는 로봇 CAD 읽기 뒤(`.finally`)에 하고, 그때 문서 visual이 그 경로가 아니면(그사이 지움) 읽지 않는다.
- 다시 찾기(`relinkFieldVisual`): 새 파일을 다 읽었을 때만 `rewriteFieldHistory`로 기록 전체의 이전 경로 visual을 바꾼다(실행 취소로 경로만 되돌아가지 않게). [다시 불러오기]는 늘 보인다(같은 경로에 고친 파일, Unity Reimport). [지우기]는 visual을 뗀다(실행 취소 한 단계).
- 잠그는 실행(`runLocksField`) 동안 [필드 CAD 불러오기…]·[다시 불러오기]·[파일 다시 찾기]는 비활성(합치기·GPU 업로드 동안 렌더러가 멈추면 키보드 게임패드 keyup이 늦는다). 정렬·지우기·단순 형상 보기는 실행 중에도 된다. 정렬·지우기는 프로젝트 열기·저장 중(`busy`)에만 비활성.
- 세 버튼 액션·열기 읽기·`applyFieldVisualStatus`는 시작할 때 잡은 `projectStore.session`이 다르면 아무것도 하지 않는다.

### 16.5 저장소(`fieldVisualStore.ts`)와 그리기

- 형상은 `geometryRegistry` 밖의 모듈 변수 칸 하나(가장 최근에 읽은 파일)이고 zustand에는 요약(`loaded`: 경로·판(revision)·메시·삼각형·투명판 수·CAD 좌표 경계 상자)만 둔다. 바꿔 끼울 때(set 먼저, 그다음 dispose)와 프로젝트를 열 때(`clearLoadedFieldVisual`)만 해제한다. 지우기는 해제하지 않아 실행 취소로 되살리면 바로 보인다. 그리기는 `fieldCadReady`(문서 visual 경로 = loaded 경로)만 본다.
- 재질(`FieldCadView.tsx`): `MeshStandardMaterial`, metalness 0.1, roughness 0.7(로봇 CAD 재질과 같은 값, 강조 없음). 색은 sRGB. 투명판: transparent, opacity 0.25, depthWrite false, renderOrder `wallPanel`(3). decal: `polygonOffset` factor −1, units −1(`POLYGON_OFFSET_UNITS.overlay`). 불투명 묶음 renderOrder 0. 클릭되지 않고 하이어라키 행이 없다. 숨김·고립 보기는 내리지 않고 `visible`만 바꾼다(재질 21개를 다시 컴파일하지 않게).
- 표시 층(`fieldLayers.ts`): `cadReady ∧ ¬elementsHidden`이면 `{cad: true, simple: 'companion', outlines: shapesShown}`, 아니면 `{cad: false, simple: 'all', outlines: false}`. `elementsHidden` = `fieldHidden`(Field 줄 눈 아이콘·H·Field 인스펙터 확인란) ∨ 고립 보기. 필드 요소를 숨기면 CAD 층을 통째로 숨기고 단순 바닥·벽·테이프로 돌아간다(CAD는 바닥·벽만 남길 수 없다).
- companion(`fieldCompanionModel`): CAD가 그리는 것(바닥·이음선·테이프·벽·구조물·시작 상태 CELL)은 빼고, 태그(앞면 쪽으로 `CAD_TAG_FRONT_OFFSET` − `TAG_FRONT_OFFSET` = 1.0 mm 더 띄움, 새 사본)·벽 라벨·넘어간 HIVE의 carrier 구조물(HIVE CELL. CAD의 HIVE는 시작 상태라 넘어간 자리를 보인다)만 남긴다. 순서는 `model.meshes` 순서. AprilTag 16(CAD 태그 판에는 무늬가 없다), 벽 라벨 4.
- 단순 형상 윤곽 `fieldShapesShown`(Field 인스펙터 [단순 형상도 보기], Unity Collider 기즈모): 켜면 시뮬레이터가 계산에 쓰는 형상(바닥·테이프·레일·판·판 이음, solid ∨ sensed ∨ occludes 구조물. 이음선·태그·라벨·표시 전용 HIVE CELL은 뺌, BIOBUZZ 56개)의 `EdgesGeometry`(각 문턱 `OUTLINE_THRESHOLD_DEG` = 1°)를 초록 `#91f48b`(`COLLIDER_OUTLINE_COLOR`) 선 두 패스(깊이 검사 켬 불투명도 0.9, 끔 0.2)로 renderOrder 6(`FIELD_RENDER_ORDER.colliderOutline`)에 그린다. 색·불투명도는 [가정: 표시만](Unity `Handles.s_ColliderHandleColor` (145, 244, 139, 210)/255). 'none'·모르는 시즌은 `resolveSeason('none')`의 공칭 벽이다. CAD 층이 그려질 때만 켤 수 있다(값은 남는다). 보기 상태라 저장하지 않고 프로젝트를 열면 버린다.
- 시즌 의존 계산(편집 자세 줄·센서·카메라 기즈모·시작 표시·시작 위치)은 `state.field` 객체가 아니라 `state.field.season` 문자열을 구독한다(4e부터 field 객체는 정렬·불러오기·경로 고침으로도 바뀐다).

### 17.2 메시 목록 규칙(`fieldViewModel(spec, hiveTipped, elementsHidden)`)

- 바닥: 평면 [−innerHalf, innerHalf]², z = 0, 불투명, 재질 색 = `floor.material.display`.
- 이음선: `floor.seams`의 각 좌표 c마다 두 띠를 z = 0.0003에 놓는다. `seamX<i>` = 사각형 [c − 1.5 mm, −innerHalf, c + 1.5 mm, innerHalf](x = c에서 Y 방향으로 뻗음), `seamY<i>` = [−innerHalf, c − 1.5 mm, innerHalf, c + 1.5 mm](y = c에서 X 방향으로 뻗음).
- 테이프: `tape[i].rect` 평면, z = 0.0003(`offField`면 `OFF_FIELD_Z` + 0.0003).
- 벽 4개(plusX, minusX, plusY, minusY), outer = innerHalf + thickness: 레일 띠마다 상자(불투명, 레일 색). ±X 벽은 벽 방향 [−outer, outer](모서리까지), ±Y 벽은 [−innerHalf, innerHalf](모서리 상자가 겹치지 않게). 판은 이음 구간 사이로 나눠 반투명 상자(`innerHalf + panelInset` → outer, Z [railBands[0][1], railBands[last][0]]). 판 이음은 `innerHalf` → outer의 기둥(레일 색).
- `elementsHidden`이 아니면: HIVE carrier 그룹(위치 pivot, 회전 [0, θ, 0]), 구조물(모양 그대로 ZYX, 원기둥은 CylinderGeometry 축 y를 자기 z로 돌림(Rx(π/2)), HIVE CELL은 반투명), 태그(평면 변 1.25·size, 변환 = 위치·회전 × Rx(π) × T(0, 0, 0.0005), 평면 +x = 태그 +x, 평면 +y = 태그 −y, 평면 +z = 태그 −z), 벽 라벨(`walls`가 null이 아닐 때 4개).
- `fieldOutlineMeshes`: 윤곽선에 쓸 역할은 floor·tape·rail·panel·panelSeam과, solid ∨ sensed ∨ occludes 구조물.

## 19. 알려진 한계·남은 일

CLAUDE.md와 `docs/assumptions.md`가 적은 것을 모았다.

### 19.1 시즌 필드(4ab)의 한계

- 득점 요소는 6a부터 GARDEN·프리로드 POLLEN만 움직이고(FLOWER·CELL 안 공은 6b, 점수는 6d) HIVE는 실행 중 넘어가지 않는다(실행 동안 고정).
- 평면 경로(충돌 형상이 없는 세계 설명)에서는 외곽·높이가 편집 자세라 펼친 팔은 벽·구조물에 닿지 않고, 로봇은 외곽 × [0, H] 프리즘이라 기운 다리 가까이에서 실제보다 최대 약 10 cm(H 18 in)–18 cm(H 29 in) 일찍 막힌다. INIT의 실제 실행은 5단계의 3D 충돌이다.
- FLOWER 회수 구멍으로 들어가는 낮은 인테이크는 모델링하지 않는다. FLOWER 고정 브래킷 `am-5860`(레일 위 Z 11.44–11.84 in, 9 mm 넓음)은 상자에 없다.
- solid가 아닌 HIVE(최저 30.65 in)·로고 판(34.07 in)·위 막대(40.95 in)는 높이와 관계없이 고정이라 CAD 높이가 30.65 in를 넘는 규칙 밖 로봇도 HIVE를 지나간다.
- 레일은 모서리 70.130 in까지만 있지만 벽은 모서리까지 이은 반평면이다. am-0481이 아닌 벽과 들어 올린 필드는 다르다.
- 바퀴 없는 로봇의 섀시는 필드와 접촉하지 않는다(관절 몸체는 5단계 충돌을 받는다). 발판 막대는 넘지 못한다고 둔다.
- 구조물 힘은 바닥 높이에 작용한다(하중 이동 없음).
- 겹친 채 시작하면 밀어내지 않고(경고만) 깊이 걸치면 빠져나가거나 통과할 수 있다. 도는 로봇은 로봇 면이 기준인 꼭짓점 앞에서 곡률 보정만큼 일찍 멈추고, 보정이 지금 속도로 낸 값이라 각가속이 큰 하위 단계에서는 µm 단위의 파고듦이 남을 수 있다(벽 행에는 보정이 없다).
- G304 전체 검사는 없다(시작 프리셋만 벽·solid·LOADING ZONE을 확인한다). 로봇끼리의 겹침·충돌은 보지 않는다(시뮬레이터는 한 로봇만 돈다).
- 새 STEP 로봇은 필드 원점(HIVE 아래)에 생기므로 시작 위치로 옮긴다.
- 실행 중 실행 취소는 문서 시즌을 바꿀 수 있다(씬 뷰·시뮬레이터는 실행의 시즌).
- 파랑 = 빨강의 정확한 Rz(π)이고 CAD 비대칭(≤ 0.016 in)은 버렸다. 실제 필드에서 줄자로 재서 확인할 일이다.
- ftc-docs에 BIOBUZZ 좌표계 그림이 아직 없다(축은 정의를 이 시즌 배치에 적용한 것).
- 실측이 필요한 값: 구조물 μ 0.4, 재질 표, HIVE CELL 재질, 테이프 폭, 로고 판 24°, 발판 막대를 넘는지.
- 시작 표시·시작 프리셋·열기·시즌 알림은 CAD 외곽(`cad.bounds`) 프리즘으로 판정하고 INIT의 `worldStartOverlap`·`worldJointStartOverlap`은 충돌체(3D, 공차 1 mm)로 판정하므로 결과가 다를 수 있다.

### 19.2 필드 CAD 보기(4e)의 한계

- 보기용이라 CAD와 시뮬레이터 형상이 다를 수 있다([단순 형상도 보기]로 확인). 이름이 다른 STEP의 투명판은 불투명이다.
- HIVE는 시작 상태로 고정이고, 넘어간 HIVE는 CAD와 단순 CELL이 함께 보인다.
- CAD의 경기 요소(POLLEN·NECTAR)·필드 밖 요소도 그리지만 시뮬레이터에는 없다(6a 공은 시즌 데이터로 따로 그린다).
- CAD 원점이 중앙 타일 윗면이 아닌 파일은 맞지 않는다(정렬은 회전만).
- "A 불러오기 → 지우기 → B 불러오기" 뒤 실행 취소로 A를 되살리면 다시 불러와야 한다.
- 같은 프로젝트에서 실행 전에 시작한 필드 CAD 읽기의 합치기는 실행 중에 끝날 수 있다(렌더러가 잠깐 멈춘다).
- 지운 뒤의 형상(공식 파일 약 54 MB)은 다음 불러오기·열기까지 메모리에 남는다. 일부가 빠진 결과는 캐시하지 않아 열 때마다 다시 변환한다.
- 프로젝트 없는 임시 씬에서 불러온 필드 CAD는 dirty가 아니라 다른 프로젝트를 열거나 앱을 닫으면 묻지 않고 사라진다(시즌과 같은 규칙).
- `'none'` 시즌의 공칭 벽은 CAD 벽보다 23 mm 바깥이다. companion 태그는 CAD 스티커 앞 1.5 mm라 가까이서 보면 판에서 떠 보인다.
- 로봇 CAD는 열 때 못 찾은 채 저장하면 저장한 사람의 절대 경로로 상대 경로를 다시 계산해 원래 상대 경로를 잃는다(필드 CAD만 고쳤다).
- 프로젝트를 여는 동안(CAD 위치 찾기) 막는 것은 필드 CAD 정렬·지우기와 불러오기 버튼뿐이라, 그사이 시즌·오브젝트를 고치면 실행 취소·dirty 없이 연 상태에 들어간다(전부터 있던 구멍).
- Field 줄에 STEP을 끌어다 놓아 필드 CAD로 불러오기와 Field 선택의 F(필드 전체 맞추기)는 없다.
- 4e의 버전: `PROJECT_VERSION` 11 도입(지금 14), `WORLD_SPEC_VERSION` 5, 사이드카 프로토콜 4. 기준 해시 일곱은 그대로다.
- 공식 필드 STEP은 FIRST 파일이라 저장소에 넣지 않는다(시험은 CAx-IF 샘플과 합성 메시, 실제 앱 E2E만 공식 파일).

### 19.3 이 문서를 만들며 본 공백(값은 있으나 근거 문서가 없는 곳)

- 로고 판 Y 크기 0.76606 m(30.16 in)의 출처, 주석의 "ACM" 약어 풀이.
- GARDEN 테이프 rect(68.585–70.585 in)와 주석이 인용한 FAC 3.5 값 68.1–70.1 in의 0.485 in 차이의 까닭.
- FLOWER 높이 22.654 in(백스톱 윗면)의 상자 Z 범위를 0부터 시작으로 둔 근거(주석은 Layer B 범위라고만 적는다).
- 다리 상자 크기의 3축 값 자체는 CAD 메시 SVD 맞춤 결과라고만 적혀 있고, 맞춤에 쓴 원본 파일·스크립트는 이 저장소에 없다.
- `EFG`·`ACM` 약어는 코드·CLAUDE.md 어디에도 풀이가 없다. `FAC`는 Field Assembly Checklist(CLAUDE.md)이자 "필드 검수 치수"(`biobuzz.ts`), `CM`은 게임 매뉴얼(`biobuzz.ts`)·Competition Manual(CLAUDE.md)이다.
- 4e의 정렬 경고 예시 치수(X 3.65 m · Y 6.38 m · Z −0.043..1.677 m)는 `cad/bbox.json`에서 온 값이라 이 저장소에서 확인할 수 없다.
